审核结论已逐条核对，与当前 HEAD `4f76551` 一致（`media_archives.py` 的 64 GiB / 1 TiB 上限、`video_transfer.py` 解压后才校验、待审核快照挂在会被级联删除的 `acquisition_run_items` 上、`_record` 覆盖了评论的 `channel_id` 等）。

## Approach（按报告编号）

### H1 压缩炸弹 / 磁盘放大（高）

文件：`backend/app/services/media_archives.py`、`backend/app/services/video_transfer.py`、`backend/app/api/provenance.py`、`backend/app/services/import_spool.py`、`backend/app/core/config.py`、`.env.example`

1. 限额进 `Settings`：`video_package_max_file_bytes`（16 GiB）、`video_package_max_total_bytes`（128 GiB）、`video_package_max_compression_ratio`（200）、`video_package_upload_max_bytes`（128 GiB），`.env.example` 同步默认值；`media_archives` 保留图片用常量，`safe_entry` 的 `maximum` 由调用方传入。
2. `import_video_package` 在**解压前**逐条校验：
   - `safe_entry(archive, entry["path"], settings.video_package_max_file_bytes)`；
   - `info.file_size` 必须等于清单 `size_bytes`，否则该条直接失败（当前是解压写盘后才比对）；
   - 清单引用路径去重：视频、封面、字幕统一记入 `used_paths`，重复引用同一路径判失败；
   - `info.compress_size == 0` 或 `file_size / compress_size > ratio` 判失败；
   - 用清单声明的**唯一**路径大小累加校验总上限，替换现在 `sum(infolist)` 的粗略判断；
   - `shutil.disk_usage` 校验剩余空间 ≥ 声明总量，不足整包失败。
3. 解压临时目录从系统临时目录改到 `Path(settings.data_dir)/"tmp"/"exports"`（与 `api/gallery.py` 图库导出一致），`TemporaryDirectory(dir=...)` 自动清理。
4. `POST /api/videos/import-zip` 增加上传上限：先看 `content-length`，再在 `spool_upload` 写入过程中累计字节超限即中断并清理目录。

### M1 视频导出并发与磁盘（中）

文件：`backend/app/api/provenance.py`、`backend/app/services/video_transfer.py`

1. `create_video_export` 先查同工作区是否已有 `queued/running` 的 `VideoExportJob`，有则 409「已有导出任务进行中」。
2. 导出临时目录改到 `data_dir/tmp/exports`，创建前用选中视频的 `size_bytes` 估算总量并检查剩余空间。
3. 权限矩阵不变（决策如上），前端不新增权限分支。

### M2 待审核期间删站点/分类导致来源丢失（中）

1. `AcquisitionAsset` 新增 `source_snapshot_json`（Text，注释「首次采集来源快照；分类删除后仍可追溯」）。
2. Telegram 与插件两条落库路径上，`run_item.asset_id` 确定后调用新 helper `_freeze_asset_source(asset, run_item)`：仅当素材快照为空、`run_item.source_snapshot_json` 有值时写入，保证「最早一条、只写一次」。
3. `asset_source` 找不到 `run_item` 时先读 `asset.source_snapshot_json`，再退回 `{"source_type": "acquisition"}`。
4. 新增「删分类后再入库仍有站点/分类」测试。

### M5 评论 external_key 变化（中）

2. `_emit_comment_media` 的 `external_key` 恢复「根频道 id:评论 id:1」，并补 `root_channel_title`。

4. 无历史数据，不需要修正脚本；交付说明里注明「升级前若已跑过新版采集需重新采集评论」这一前提不适用于本库。

### M6 transport_type 分不出发送形式（中）

文件：`backend/app/services/telegram.py`、前端 `MediaSource.tsx`、`docs/agents/模块/采集中心.md`

直接用采集侧已有的「消息形式 / 文件形式」判断，不再按 mime、后缀或 `DocumentAttributeVideo` 猜。Telethon 的 `message.photo`、`message.video`、`message.gif`、`message.document` 本身就是互斥的消息形式（`video` 即带 `DocumentAttributeVideo` 的 document，`document` 分支就是「以文件发送」的图片或视频）——这与 `message_media_type`（`telegram.py:208-233`）里先判 `photo`、再判 `video`、最后落到 document 的顺序一致，`document` 分支正是后续为采集文件形式媒体新增的判断。

新增 `message_transport_type(message)`：

- `message.photo` → `photo`
- `message.video` → `video`
- `message.gif` → `animation`
- `message.document` → `document`
- 其余 → `None`（`_record` 只在有媒体时调用，实际不会为空）

`_record` 改用它填 `transport_type`，保证「媒体类型」和「发送形式」用同一套分支、不会互相矛盾；前端 `values` 补 `animation`，`docs/agents/模块/采集中心.md` 把发送形式说明改为「照片 / 视频 / 动图 / 文件」。

### 低风险项

- **L1**：待定；此前实现保持现状，不代表用户已决定不做。
- **L2**：`normalize_snapshot` 超 64 KiB 时按顺序裁剪并打标记，不再抛错：先丢 `public_metadata`（记 `metadata_truncated`）→ 再丢 `upstream`（记 `upstream_truncated`）→ 再截断长字段/标签列表；正常大小的快照行为不变。
- **L3**：`api/gallery.py` 的 `_resolve_gallery_export_photos` 增加 `selectinload(GalleryPhoto.provenance).undefer(MediaProvenance.snapshot_json).selectinload(MediaProvenance.telegram)`，消除导出时每图 N+1。
- **L4**：`asset_source` 对没有 `provenance` 的旧截图，按 `capture.video_asset_id` 回溯原视频素材的来源快照（只回溯一层，防自引用）。
- **L5**（见决策）：导出处过滤 `processing`、`processing_failed`。导入时新增 `VideoService.playback_optimization_needed(path, filename)`：
  - `video_faststart_enabled` 关闭 → 不需要；
  - `_probe_video` 失败 → 需要（交给现有流程报错）；
  - 非浏览器友好编码且 `video_transcode_non_browser_friendly` 开启 → 需要；
  - `_has_faststart_moov(path)` 非 True → 需要；
  - `_should_optimize_for_seek(path, info)` 为真 → 需要；
  - 否则视为已适合当前环境，直接置 `ready`（同现有「已优化」语义）。
  需要优化时沿用采集入库的既有做法：`db.commit()` 后调用 `video_service.optimize_video_faststart(video.id)`，异常回滚并把状态置 `processing_failed`、原因写入 `result["warnings"]`。
- **L6**：`cleanup_exports` 增加 `workspace_id` 参数；列表/详情只清理当前工作区，全量清理保留在启动（`lifecycle.recover_exports`）和创建导出前。
- **L7**：`SECRET` 正则补 `auth`、`jwt`、`sig`、`hmac`、`nonce`、`api key` 等（带词边界，避免误伤 `plugin_key`）；凭据文本检测补 `x-api-key:`、`signature=` 形态。
- **L8**：`frontend/src/components/MediaSource.css` 增加 `.video-export-selection` 样式（小徽标式复选框，不挤压封面）。
- **L9**：待定；此前未改代码，交付说明仍需写明「升级会重建 5 张表、`downgrade` 会删来源表、建议先备份 `app.db`」。
