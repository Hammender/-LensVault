## Context

`gallery_photos` 只保存对象键和图片尺寸，现有相似整理在读取图库图片时没有文件大小可展示。采集中心的站点、分类、运行记录接口返回全量数组，页面也全量渲染；但创建和配置表单仍依赖完整的引用数据。

## Goals / Non-Goals

**Goals:**

- 为图库图片持久化保存原始文件大小并补齐历史缺失值。
- 在相似整理的大图信息栏提供该大小。
- 让三个采集管理列表按页从服务端读取，且不破坏现有表单数据来源。

**Non-Goals:**

- 不修改对象存储中的任何对象，不重跑相似扫描，也不改变相似度判定。
- 不为站点、分类、运行记录加入搜索或筛选能力。
- 不将表单和导出范围选择改为分页选择器。

## Decisions

- 在 `gallery_photos` 增加可空 `size_bytes`。可空支持平滑升级和回填失败重试；所有新导入路径从已读取的载荷直接写入字节数。图库响应模型承载该字段，因此相似分组复用图库映射时自动获得大小。
- 提供位于 `backend/app/tools` 的一次性回填脚本。脚本通过对象存储的 `stat_object` 获取大小，仅处理缺失值；默认预演，只有 `--apply --confirm` 才提交更新，并为失败项输出审计记录。相比启动时全量回填，这避免阻塞服务启动和意外大量写库。
- 保持 `/sources`、`/categories`、`/runs` 的数组响应不变，新增 `/page` 分页读取端点，统一返回 `items`、`total`、`offset`、`limit`。这避免破坏既有表单、导出和调用方。
- 前端对三类管理列表各自维护分页状态，默认每页 20 条；创建、编辑、删除和启动运行后刷新当前对应页，删除后通过总数钳制偏移量。完整引用数组继续单独刷新给下拉框使用。

## Risks / Trade-offs

- [历史对象不存在或存储不可达] → 记录审计失败并保留空值，脚本可再次执行。
- [保留全量引用数据仍有请求成本] → 这是保持现有表单行为的兼容选择，主要无限增长的列表 DOM 与主列表请求已分页。
- [已有相似扫描不会自动重跑] → 相似分组响应读取当前图库图片数据，回填后重新打开或刷新结果即可显示大小。

## Migration Plan

1. 服务启动时补充可空字段，旧记录保持为空且可正常读取。
2. 部署后手工以预演模式执行回填脚本，确认审计结果后以显式确认参数写入。
3. 如需回滚，代码可继续容忍空值；数据库字段保留，不删除已写入的大小数据。
