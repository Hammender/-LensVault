## Why

相似扫描耗时较长，用户在扫描期间手动删除图片时，旧的候选集合仍会在发布结果阶段引用已删除图片，导致 SQLite 外键约束使整个扫描失败。相似整理页删除图片后也未局部同步分组卡片，批量处理体验不连贯。

## What Changes

- 扫描发布阶段容忍候选图片被删除，保留仍有效的相似组而不是使整次扫描失败。
- 删除图片后同步维护相似组及扫描统计，并提供单个相似组的最新读取接口。
- 相似整理页支持按组删除已选图片、确认删除，并只刷新受影响的组卡片。
- 将 SQLite 数据库 URL 与运行数据目录改为必须在 `.env` 中配置，移除代码硬编码默认路径。
- 前端不再直接展示数据库原始异常。

## Capabilities

### New Capabilities

- `gallery-similarity-review`: 展示图相似扫描、相似组持久化与人工删除审核。

### Modified Capabilities

- 无。

## Impact

- 后端相似扫描服务、图库删除清理逻辑、相似组读取 API 和配置加载。
- 前端相似整理页、请求封装和交互样式。
- SQLite 与现有相似扫描结果数据；不新增外部依赖。
