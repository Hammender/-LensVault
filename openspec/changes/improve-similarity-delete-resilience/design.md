## Context

相似扫描先读取图库图片并进行耗时的视觉特征计算，最后把候选聚类发布为 SQLite 相似组。扫描期间，用户可以通过图库删除接口删除任意图片；目前发布阶段仍直接写入旧图片 ID，触发外键失败并回滚全部结果。相似整理页复用图库批量删除接口，但删除成功后只恢复扫描概览，不会重新加载同一扫描 ID 的分组列表。

运行时配置仅允许读取项目 `.env`，但 `Settings` 仍保留 SQLite 路径和数据目录的硬编码默认值。项目使用 SQLite 外键、FastAPI 后台任务、React 状态更新；实施期间不得启动前后端服务。

## Goals / Non-Goals

**Goals:**

- 扫描期间删除候选图片后，保留其余有效相似组并正常完成扫描。
- 删除后只更新受影响相似组卡片，支持按组确认删除已勾选图片。
- 让 SQLite 数据库和数据目录的运行时位置完全由 `.env` 决定。
- 不向用户暴露原始 SQL 异常。

**Non-Goals:**

- 不恢复用户手动删除的图片，不自动删除相似图片。
- 不修改 DINOv2、相似阈值、分组算法或 Qdrant collection。
- 不增加全量结果实时推送或后台自动重扫。

## Decisions

### 在最终发布窗口重新校验并原子写入成员

发布前按 workspace 查询仍存在的图库图片，剔除已删除成员；基于剩余成员重新选择代表图和建议保留图，成员少于两张则跳过组。成员使用“从仍存在的图库行选择并插入”的原子 SQL 写入，避免先检查后删除导致外键再次失败。

发布前进入短 SQLite 写事务以串行化最后的校验、组写入和扫描完成状态。相比捕获外键异常后重跑整次扫描，该方案保留已完成的特征计算，并让用户删除在锁释放后走既有清理路径。

### 为局部卡片刷新提供单组读取

新增受 workspace 隔离的单组读取接口，返回相似组或空结果。删除完成后，前端只请求当前已删除图片所在的组，并在本地替换或移除该卡片；只有删除导致当前分页没有任何组时才加载相邻有效页。

相比每次删除重新加载整页或浏览器刷新，单组读取能同步后端重新计算的建议保留标记，并保留其他卡片、预览和筛选状态。

### 复用批量删除接口并保持两种删除入口

组头“删除图片”仅处理该组中勾选的图片；顶部跨组批量删除保留。两者都调用现有批量删除 API，之后按受影响组进行局部同步，并清除已删除图片的选择状态。

### 移除存储路径默认值

将 `DATABASE_URL` 和 `DATA_DIR` 声明为 `Settings` 必填字段，继续使用现有 `.env` 完整字段校验。`.env` 保留实际路径，`.env.example` 只给出非隐私 SQLite URL 和目录示例。相比隐式默认值，缺失配置会在启动前明确失败。

### 错误信息分层

服务日志保留异常堆栈供排障；扫描记录和任务消息只保存可行动的中文摘要。前端通知直接展示该摘要。

## Risks / Trade-offs

- [用户在发布窗口请求删除] → SQLite 写事务短暂串行化，发布完成后删除继续执行并清理新组。
- [删除后某组不足两张] → 后端删除该组，单组读取返回空结果，前端移除卡片并修正分页。
- [同一图片出现在当前页多个组] → 前端记录所有受影响组并逐个局部刷新。
- [旧扫描统计与实际组数不一致] → 删除清理完成后重新统计受影响扫描的组数并标记过期。
