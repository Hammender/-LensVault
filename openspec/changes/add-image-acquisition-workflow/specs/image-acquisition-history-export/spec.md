## ADDED Requirements

### Requirement: 成功入库图片溯源
系统 SHALL 为每个成功导入的图片保存采集运行、临时资产、站点和分类快照，以及可空的正式图库图片关联。正式图库图片删除时，系统 MUST 保留溯源记录并将关联置空。

历史视图的图片数量和导出 MUST 按采集资产或图库图片去重，不得把同一图片关联多个运行产生的来源关系行数误报为图片数量。图库精确重复淘汰项和导入失败项 MUST NOT 进入成功入库历史或 ZIP。

#### Scenario: 查询一次运行的成功入库图片
- **WHEN** 用户查看某次已完成采集运行的历史记录
- **THEN** 系统仅展示该运行中已成功进入正式图库的图片及其来源、分类和当前可用状态

#### Scenario: 已入库图片随后被图库删除
- **WHEN** 某个具有关联的正式图库图片按既有图库流程删除
- **THEN** 系统保留采集历史快照、解除当前图库关联，并在历史视图中标识该文件不可用

#### Scenario: 按入库批次浏览溯源
- **WHEN** 用户进入“入库与导出”并选择一个入库批次
- **THEN** 系统分页展示该批次的逐图结果，且每张资产只占一行，展开后可查看其全部采集来源、处理结果和当前图库可用状态

#### Scenario: 浏览没有批次关联的旧版入库记录
- **WHEN** 成功入库溯源没有对应的成功入库批次项
- **THEN** 系统将这些资产汇总到“历史导入（未关联批次）”虚拟批次并允许分页查看

#### Scenario: 大量批次和图片不拉长页面
- **WHEN** 入库历史包含大量批次或大量图片
- **THEN** 入库批次和批次溯源区域分别限制可视高度、提供内部滚动和分页，批次行不直接列举逐图文件名

### Requirement: 范围化临时 ZIP 导出
系统 SHALL 允许具有工作区访问权限的用户按采集运行、站点、分类或日期范围请求导出成功入库图片。系统 MUST 只导出当前仍存在于正式图库的图片，并 MUST 在 ZIP 中写入包含范围、统计、来源和缺失项目的 `metadata.json`。

#### Scenario: 导出指定采集运行
- **WHEN** 用户请求导出一次采集运行的成功入库图片
- **THEN** 系统创建异步导出任务并生成只含当前可用正式图库图片的 ZIP，同时在元数据中记录缺失图片

#### Scenario: 浏览历史时仍可直接创建导出
- **WHEN** 用户在“入库与导出”页面查看批次或逐图溯源
- **THEN** 创建导出表单和导出任务列表始终在下方全宽区域可见，且导出日期条件不随批次筛选变化

### Requirement: 大文件导出和临时清理
系统 SHALL 逐文件流式写入 ZIP，MUST 不将完整 ZIP 保留在应用内存中。完成的 ZIP MUST 先上传为 MinIO 临时对象；下载成功后系统 MUST 删除该对象，未下载或中断的临时对象 MUST 在配置的 TTL 后清理。

#### Scenario: 浏览器下载完成
- **WHEN** 用户通过受权下载接口完成导出 ZIP 下载
- **THEN** 系统向浏览器流式返回文件并删除对应的 MinIO 临时对象

#### Scenario: 导出任务被遗留
- **WHEN** 已完成导出任务的临时对象超过配置 TTL 且未下载
- **THEN** 系统清理该临时对象并在任务记录中标记其已过期
