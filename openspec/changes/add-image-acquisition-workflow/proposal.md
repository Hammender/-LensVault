## Why

当前图库图片需先由独立脚本下载到本地目录，再人工筛选、导入和与既有图库整理。这个流程无法可靠处理网站增量更新、采集来源追溯、重复图片和历史导出，且临时文件与正式图库之间的边界不清晰。

本次变更在 PictureShow 中增加独立的图片采集与审核工作流，将已验证站点的采集能力、去重、相似整理和人工确认串成可维护的闭环，同时保持正式图库现有的识别与删除语义。

## What Changes

- 新增独立的采集站点、采集脚本定义、站点脚本绑定、采集分类网页、采集运行、采集图片和来源条目管理能力；一个站点可绑定多个同网页格式的受信任脚本。
- 首批接入 `raindrop-ftxsri-workers-dev` 与 `shfwzwz-raindrop-page` 两个现有 Raindrop 脚本，并提供将 `catchPics` 的历史资源和状态无损迁入采集工作区的命令行工具。
- 采集分类名称仅用于界面辨识，脚本运行只接收分类的真实 URL 和脚本声明的参数；前端根据参数元数据动态生成运行表单。
- 采集图片先保存到 MinIO 临时工作区，按 SHA256 去重；提供客观质量提示、相似图片整理以及人工导入、丢弃操作。
- 审核确认后将图片提升到正式图库并复用已有图库识别流程；保留一次采集对应哪些图库图片的溯源关系，而不将采集分类绑定为人物或标签。
- 新增按采集批次、站点、分类或日期范围导出已成功入库图片的异步 ZIP 导出能力，使用临时 MinIO 对象并自动清理。
- 为人工入库增加持久化批次和逐图结果，确保后台异常时不会丢失选择，并提供失败隔离、重试和启动恢复。
- 将采集统计拆分为可核对的扫描、下载和唯一资产漏斗，提供互斥资产状态总览。
- 新增采集页面及相应权限、运行恢复与清理机制；不引入定时调度、任意脚本执行或“个人喜好”自动判定。

## Capabilities

### New Capabilities

- `image-acquisition`: 受信任采集源的配置、增量运行、临时存储、去重和运行状态管理。
- `image-acquisition-review`: 采集候选的质量提示、相似整理、人工审核和提升至正式图库的流程。
- `image-acquisition-history-export`: 已成功入库图片的溯源查询与临时 ZIP 导出。

### Modified Capabilities

- 无。

## Impact

- 后端将增加采集领域模型、数据库迁移、站点适配器、采集/审核/导出服务及 API，并扩展 MinIO 存储能力和运行期恢复逻辑。
- 前端将增加采集中心入口、来源与分类维护、运行列表、审核工作台、历史与导出界面。
- 配置将新增采集下载、质量提示和导出临时文件相关字段；本地 `.env` 与 `.env.example` 均需同步维护。
- 依赖现有 SQLite、MinIO、图库导入和相似度服务，但不改变现有图库删除、人物识别的业务含义。
