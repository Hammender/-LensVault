## Context

当前相似整理把像素数量和拉普拉斯方差直接相加作为质量分。该方法会把压缩噪点、锐化光晕和纹理噪声当作清晰细节，且推荐结果没有置信边界。图库与采集区还分别组织相似组，需要共享同一套评分语义。

项目已经具备 OpenCV 图像处理和 InsightFace 人脸检测、识别能力，因此本次改动不新增模型依赖。图库存在已确认的人物与人脸记录，采集区则没有人物上下文，两者必须采用不同的人脸启用条件。

## Goals / Non-Goals

**Goals:**

- 用 0 至 100 分的多指标整体质量分替代旧的像素数加拉普拉斯方差分数。
- 在身份和主体均明确时，以整体质量 55%、人脸质量 45% 生成组内综合分。
- 对路人、多人不明确、检测失败等情况自动回退为仅整体质量。
- 最高分相对第二名不足 3 分时不产生建议保留项。
- 普通相似与镜像相似共享完全一致的质量方向和推荐规则。
- 在接口和界面展示评分构成与未推荐原因。

**Non-Goals:**

- 不引入人体检测、人体实例分割或姿态模型。
- 不依据文件体积、文件名或创建时间判断清晰度。
- 不把质量评分用于判定两张图片是否相似；相似度检测逻辑保持独立。
- 不承诺对审美、构图、表情或内容价值进行评分。

## Decisions

### 1. 使用共享的可解释图像质量评估器

整体评估在 EXIF 方向校正后进行，并将长边限制在分析尺寸内，避免不同原图尺寸造成不必要的内存和计算开销。评估器输出有效分辨率、梯度细节、噪点、块效应和曝光五类归一化指标，再组合为 0 至 100 分。

细节得分使用 Sobel 梯度，不再单独依赖拉普拉斯方差；高频细节必须同时通过噪点与块效应惩罚，避免噪点和过度锐化抬高最终分。有效分辨率保留，但采用有上限的对数映射，防止超大图片仅凭像素数压倒其他指标。文件字节数完全不参与计算。

备选方案是接入无参考图像质量神经网络。该方案需要新增较大的模型和推理链路，部署与性能成本高，且目前已有指标足以修复已知偏差，因此不采用。

### 2. 人脸质量复用现有人脸能力，但采用严格启用条件

人脸裁剪复用同一质量评估器，输出单独的人脸质量分。人脸区域不替代全图，而只在满足条件时按 `0.55 * 整体分 + 0.45 * 人脸分` 合成。

图库指定人物范围时，只采用每张图片中已确认匹配该人物、无需复核且面积足够的人脸。未指定人物时，必须存在一个在组内每张图片都可靠出现且主体明确的人物，否则整组禁用人脸加权。

采集区没有已确认人物标签，因此每张图片必须只有一个明显主脸，且主脸面积相对第二张脸达到优势阈值；随后使用现有 InsightFace 向量验证各成员主脸为同一人。任意成员不满足条件，整组回退为仅整体质量。该规则有意偏保守，以避免把路人或合照中的任意人物用于推荐。

备选方案是选择最大人脸而不做身份校验。该方案在多人照片和不同拍摄角度下容易选择不同人物，因此不采用。

### 3. 推荐是组级决策，不等同于代表图

每个成员先得到组内最终质量分。排序第一与第二的差值达到配置阈值（默认 3 分）时，第一名才标记为建议保留；否则组状态为“质量接近”，所有成员的建议保留均为否。

用于相似度展示和比较的代表图仍必须存在，可选择最高质量成员，但不得因为它是代表图而自动成为建议保留项。删除成员后按同样规则重新计算推荐。

### 4. 缓存质量版本并兼容旧数据

图库相似特征增加独立质量算法版本和评分明细，避免仅修改质量算法就触发 DINO 向量重建。采集资源保存整体分、主脸分、主脸是否明确及用于组内身份核验的向量。数据库启动兼容逻辑为现有表补列，`sql/tables.sql` 同步更新。

旧记录在下次相似扫描时按新版本惰性重算。重算前缺少明细的历史组按仅整体旧数据展示，不伪造人脸评分。

### 5. API 返回评分构成和推荐状态

成员接口返回整体质量分、人脸质量分、最终质量分和是否建议保留；组接口返回人脸评分是否启用、推荐状态及推荐依据。前端据此显示“整体”“人脸”和“质量接近”等信息，不根据文件大小自行推断。

## Risks / Trade-offs

- [指标权重无法覆盖所有拍摄类型] -> 使用有界指标与保守推荐阈值，并保留评分明细便于后续用真实样本校准。
- [人脸检测增加扫描耗时] -> 只在质量版本失效时计算并缓存；图库优先复用已有已确认人脸记录。
- [采集区主脸向量增加数据库空间] -> 仅保存单个明确主脸的 float32 向量，不保存全部检测结果。
- [严格条件导致很多组没有人脸分] -> 这是预期行为；证据不足时整体评分比错误选择路人更可靠。
- [旧组推荐在重扫前仍使用旧结果] -> 版本失效后由扫描惰性更新，并在接口中对缺失的新明细采取无强推策略。

## Migration Plan

1. 启动兼容逻辑为图库相似特征、相似组成员和采集资源补充质量字段。
2. 部署代码和配置，将质量版本设置为新版本、推荐最小分差设置为 3 分。
3. 用户下次运行图库或采集区相似扫描时自动重算相关质量缓存和推荐。
4. 如需回滚代码，新增列可保留且不会影响旧版本读取；不执行破坏性数据回退。

## Open Questions

无。初始指标权重和主脸优势阈值作为代码常量并通过测试固定，后续应基于真实误判样本单独提出校准变更。
