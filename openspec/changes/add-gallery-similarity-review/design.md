## Context

当前展示图库通过 `(workspace_id, sha256, is_rich_text)` 防止同类型文件的完全重复，但无法识别截图、重编码、缩放、裁剪或同一场景下的近似连拍。图库已经具备人物标签、后台任务、MinIO 原图、缩略图、批量删除和 Qdrant 人脸向量能力，因此可以在现有边界内增加独立的整图相似度管线。

当前本地数据约有 6,673 张展示图、164 个带图片人物，按同人物去重后约 78.3 万个候选图片对，单个人物最多 508 张。运行环境为 Python 3.11、RTX 5060 Ti 16GB，适合使用 DINOv2 Base 做批量特征提取。仓库约束要求程序只读取 `.env`、模型不得提交、不得在实施过程中主动启动前后端。

## Goals / Non-Goals

**Goals:**

- 找到截图/缩放/压缩/裁剪形成的近重复图，以及同场景下姿势、表情、角度和光影略变的冗余图。
- 优先限制在共享人物标签的图片集合中，降低计算量与语义误报。
- 以持久化照片组供用户逐组审核，任何删除必须由用户明确确认。
- 缓存图片特征，使后续重扫主要处理新增或算法版本变化的图片。
- 使用独立 Qdrant collection，保持整图向量与人脸向量生命周期隔离。

**Non-Goals:**

- 不自动删除图片，不根据分数自动勾选删除项。
- 第一版不提供文字搜图、通用语义检索或跨人物标签的全图库聚类。
- 第一版不在上传后自动增量重建分组，也不增加定时调度器。
- 不保证复刻特定手机厂商的私有算法，只提供可校准的本地实现。

## Decisions

### 采用两级混合检测

近重复层使用 EXIF 归一化后的 pHash、dHash 和 OpenCV ORB。感知哈希能低成本筛选重编码与缩放变体，ORB 用局部特征和几何一致性确认截图及裁剪。相比只用 SHA-256，这些特征对像素级变化更稳健；相比直接对所有候选运行深度模型，也更容易解释近重复原因。

同场景层使用 `facebook/dinov2-base` 的 768 维 CLS 特征和余弦相似度。DINOv2 更偏视觉结构和外观，适合本需求；CLIP 更偏图文语义，可能把同一人物或同一地点的大量不同照片都拉得过近。近重复结果会先被提取，剩余照片再进入同场景聚类，避免重复展示。

### 模型本地化与 CUDA 推理

模型固定下载到 `E:/AI-MODELS/vision/dinov2-base`，服务通过 `.env` 获取路径并以 `local_files_only=True` 加载。默认 CUDA、FP16 autocast、批量 32；显存不足时逐级减半，CUDA 不可用时回退 CPU。实施时安装支持 RTX 50 系的 PyTorch CUDA 12.8 版本并实际验证，不在运行时联网下载。

### 特征存储与结果存储分离

DINOv2 向量保存在新的 `pictureshow_gallery_similarity_dinov2_base_v1` Qdrant collection，大小 768、距离 Cosine。SQLite 保存图片特征状态、感知哈希、质量指标、扫描批次、分组、关联人物和成员分数。这样 Qdrant 负责高维向量，关系库负责事务、一致性和 UI 查询。

每个图片向量使用由 workspace、图片 ID 和模型版本生成的确定性 point ID。Qdrant payload 至少包含 workspace ID、图片 ID、SHA-256、图库类型和特征版本。删除图库图片时同步清理向量。

### 候选范围与聚类

候选图片必须共享至少一个人物标签。用户可选择一个人物或全部人物；默认普通图与图文图隔离，打开跨类型开关后才允许互相比对。

使用 complete-link 方式构组，新成员必须与组内全部成员达到对应阈值，避免仅靠连通分量产生链式误合并。多人扫描得到完全相同成员集合时合并分组并保留全部关联人物。组名不持久化人物名称，而由人物当前名称和组序号动态生成。

### 质量推荐不参与删除决策

对归一化缩略图计算 Laplacian 清晰度，并结合像素面积生成组内质量分数。每组只标记一个“建议保留”成员；该标记不自动选中其他图片，也不改变删除 API。推荐图被删除后，对剩余成员重新选择。

### 扫描版本与过期策略

扫描复用现有 Task 表报告进度，并通过独立扫描记录关联参数和结果。图片导入、删除、人物标签增删会把受影响的已完成扫描标记为过期。用户手动重扫时旧结果继续可读，新扫描全部成功后在事务内替换同范围旧结果；失败时保留旧结果。

### API 与权限

使用 `/api/gallery/similarity-scans` 创建和读取扫描，结果按组分页。读取结果需要 workspace 成员权限，发起扫描需要 `can_edit_gallery`，删除成员继续通过现有批量删除接口并要求 `can_delete_gallery`。API 只返回图片 ID 和现有媒体 URL，不暴露 MinIO 内部路径。

## Risks / Trade-offs

- [真实图库阈值与通用默认值存在偏差] → 阈值全部放入 `.env`，提供真实图库候选评估工具，并以不自动删除作为最终安全边界。
- [DINOv2 可能把场景相似但值得保留的照片归为一组] → 限制同人物候选、使用 complete-link、明确区分两档，并只提供人工审核。
- [后台任务在进程重启时中断] → 启动时将未完成相似扫描标记失败，旧扫描结果保持可用。
- [Qdrant 与 SQLite 写入无法形成分布式事务] → 先幂等写特征向量，再在 SQLite 事务中发布扫描结果；失败任务可安全重跑并覆盖确定性 point ID。
- [CUDA/PyTorch 与 RTX 50 系兼容问题] → 使用 CUDA 12.8 wheel，安装后实际执行 CUDA 向量生成自检，失败时保留 CPU 回退。
- [同一图片带多个人物标签可能重复参与扫描] → 按成员集合去重完全相同的组，保留关联人物列表。

## Migration Plan

1. 新增依赖和配置字段，先更新本地 `.env`，再同步非隐私 `.env.example`。
2. 下载 DINOv2 Base 并验证 CUDA 推理与 768 维输出。
3. 通过应用现有 SQLite 启动迁移风格创建新表和索引，不修改已有图库记录。
4. 创建并校验独立 Qdrant collection；不触碰人脸 collection。
5. 发布 API 和前端入口。首次进入时没有结果，用户手动发起扫描。
6. 回滚时可停止使用新入口并删除新增关系表与独立 Qdrant collection；图库原图、人脸记录和现有功能不受影响。
