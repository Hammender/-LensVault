## Context

图库扫描目前按共享人物标签生成候选，通过 pHash、dHash、ORB 判断近重复，通过 DINOv2 判断同场景；待审核区目前只支持全部待审核图片之间的普通相似扫描。待审核图片约数千张、图库图片约上万张，联查不能采用图库全量两两比较。

## Goals / Non-Goals

**Goals:**
- 两个现有页面均能独立执行普通相似和水平镜像相似检查。
- 待审核区支持区内检查与待审核对图库的定向联查。
- 镜像后轻微缩放、压缩的图片仍按现有近重复标准识别。
- 临时镜像不影响原图质量评价，联查不产生图库内部冗余计算。

**Non-Goals:**
- 不支持垂直翻转、旋转或任意透视变换。
- 不自动删除或自动勾选图片。
- 不把镜像相似扩展到 DINOv2 同场景结果。

## Decisions

1. 在现有扫描接口增加 `scan_type`，而不是新建顶层镜像接口。图库与待审核页面可以复用任务状态、历史结果、分组审核和权限体系，默认值 `normal` 保持兼容。
2. 水平镜像只在内存解码像素上执行。分别计算原图和镜像图的比较特征，质量、尺寸和建议保留分只读取原始图片，因此不会发生重编码或清晰度下降。
3. 镜像判定复用近重复链路：pHash/dHash 召回，必要时由 ORB 局部特征提升；不使用 DINOv2 同场景档。每对图片同时比较普通和镜像得分，镜像得分达阈值且高于普通得分才标记镜像；近似对称导致两者接近时由普通结果处理。
4. 待审核扫描增加 `scope`。`pending_only` 只产生待审核之间的边；`pending_to_gallery` 只以待审核图片为查询端产生待审核到图库的边，禁止待审核内部和图库内部配对。
5. 联查通过图库已有特征和 Qdrant 向量索引召回候选，不做待审核数量乘图库数量的全量特征级比较。普通联查可使用哈希近重复和 DINOv2 同场景候选，镜像联查只使用镜像哈希与 ORB。
6. 扫描批次持久化类型与范围，结果成员显式记录 `pending` 或 `gallery` 来源。图库成员在待审核结果中只读，批量丢弃只接收待审核资产 ID。

## Risks / Trade-offs

- [近似对称图片的普通与镜像得分接近] → 优先归入普通相似，避免宣称无法可靠判断的方向关系。
- [哈希索引召回可能遗漏大幅裁剪图片] → 使用与现有近重复一致的阈值和 ORB 复核，本期目标仅覆盖轻微缩放、压缩和裁剪。
- [旧扫描记录没有类型与范围] → 数据迁移填充 `normal` 与既有范围，旧接口调用继续得到原行为。
- [图库特征缺失] → 扫描按现有特征任务补齐；单图不可解码时记录进度错误并使本次扫描失败，保留上次成功结果。

## Migration Plan

新增扫描类型、范围及跨来源成员所需字段和约束，迁移既有记录为普通区内扫描；同步更新 SQLAlchemy 模型和 `sql/tables.sql`。回滚时先停止新扫描，再回退接口与迁移；原始图片和图库对象不受影响。
