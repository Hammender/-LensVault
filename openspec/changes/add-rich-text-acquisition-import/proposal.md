## Why

图片采集待审核区目前只能把候选图片导入为普通图片，用户若希望保留图片中的文字信息，只能先导入再通过其他流程处理，无法复用图库已有的图文图片、OCR 和系统标签能力。需要让采集导入在提交时明确目标图片类型，并让该类型贯穿异步批次、失败重试和进程恢复。

## What Changes

- 在采集待审核区增加“普通图片 / 图文图片”批量导入类型选择，所选类型作用于当前选中的整批图片。
- 扩展采集导入 API，使其接收目标图片类型；未提供类型时保持按普通图片导入的兼容行为。
- 在采集导入批次中持久化目标图片类型，并在历史记录中展示该类型。
- 按目标类型执行图库精确重复检查：普通图片与图文图片可拥有相同文件内容，同一类型内仍按现有规则去重。
- 图文导入复用图库现有图文处理流程，包括 `#图文` 系统标签、OCR 状态和后续识别处理。
- 保持采集阶段针对图库普通图片的现有精确重复过滤行为不变。

## Capabilities

### New Capabilities

- `acquisition-rich-text-import`: 规定采集候选图片按批次选择普通或图文类型导入、类型持久化、目标类型去重及历史展示行为。

### Modified Capabilities

无。

## Impact

- 后端采集 API、请求模型、导入批次模型、异步导入与恢复逻辑。
- 数据库生命周期迁移及 `sql/tables.sql` 全量表结构。
- 前端采集待审核区、导入失败重试和采集历史展示。
- OpenAPI 定义、前端类型及采集流程自动化测试。
