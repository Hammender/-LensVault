## Context

当前 InsightFace `buffalo_l` 以 640×640 检测人脸并生成 512 维归一化向量，Qdrant 使用余弦距离保存人物样本。图库识别只查询一条最近向量，载荷没有工作空间信息；人工给图片添加人物不会形成正式样本；重新识别会先清理旧结果再执行模型。现有 Qdrant 集合规模很小，使用精确扫描，因此数据库近似索引不是当前准确率下降的主要原因。

## Goals / Non-Goals

**Goals:**

- 保证索引只包含正式样本与人物中心，并按工作空间和模型版本隔离。
- 通过人物级候选聚合和多样化样本提高熟人召回率。
- 让人工纠正可选择晋升为正式样本，并自动形成评测标签。
- 保证重新识别失败不会破坏旧结果或手动标签。
- 提供可重复的离线参数与模型评测能力。

**Non-Goals:**

- 不使用图库中未经确认的人脸扩充索引。
- 不在当前小样本数据上训练或微调 ArcFace。
- 不引入生成式人脸修复。
- 不在本变更中自动下载或切换新的人脸模型。

## Decisions

1. **版本化样本索引**：新集合载荷保存 `workspace_id`、`person_id`、`source_type`、`sample_photo_id` 和 `embedding_version`。通过全量重建验证后切换配置，避免在旧集合上原地迁移不完整载荷。
2. **只索引正式参考数据**：`sample` 点来自样本库照片，`centroid` 点由同一人物的有效样本平均并重新归一化得到。展示图库 FaceRecord 永远保持 `vector_collection = NULL`。
3. **人物级检索**：查询前 50 个样本候选后按人物取最高分；中心融合先作为评测候选，不直接修改生产评分。记录前两名人物和分差，为校准及问题诊断提供数据。
4. **显式两步晋升**：图片详情的人工人物标签只建立图片关系。标签保存后，用户可通过独立按钮将恰好一张有效人脸加入样本库；已晋升样本可单独撤销而不删除图库照片或人物标签。
5. **先算后换**：重新识别先在数据库事务外完成对象读取、检测和匹配，得到完整计划后才在事务中替换自动记录；失败则不触碰旧数据。
6. **自然使用形成标签**：人工纠正记录原预测、候选分数和最终人物。离线评测结合这些事件、样本留一法和人物留出法，不把“未修改”当成正确标签。
7. **保守发布**：初始仍使用 `buffalo_l`、640、阈值 0.45、无翻转增强。只有评测达到样本量和质量门槛才输出参数建议，不自动更新生产配置。

## Risks / Trade-offs

- **中心向量可能稀释特殊角度特征** → 中心融合先以影子方案评测，生产默认仍使用最佳单样本分数。
- **图库图片晋升可能复制存储** → 仅在点击独立按钮时创建裁剪样本，并复用现有对象存储流程；撤销时同步清理派生对象和参考向量。
- **图库检测框在裁剪后可能无法复检** → 按检测时的原始像素坐标裁剪，显式应用 EXIF 方向，并以人脸最长边约 2 倍的正方形区域开始、零人脸时扩大到约 3 倍重试。
- **自然积累标签较慢** → 结合样本留一法提供早期基线，并在数据不足时禁止给出生产建议。
- **1024 检测和翻转增加耗时** → 报告同时展示准确率与耗时，模型替换限制为不超过基线两倍。
- **旧集合载荷不完整** → 使用新集合重建及数量校验；失败时继续使用旧集合。

## Migration Plan

1. 添加数据库字段/事件表和新配置，保持现有接口参数向后兼容。
2. 创建版本化 Qdrant 集合，从有效样本重建 `sample` 与 `centroid` 点。
3. 校验每个工作空间、人物和样本数量后切换集合配置；旧集合暂时保留供回滚。
4. 部署人物级检索、显式晋升和安全重新识别。
5. 积累评测事件并运行离线报告，人工确认配置变更后再启用实验策略。

## Open Questions

无。生产默认值、晋升限制、评测门槛和模型切换标准均已确定。
