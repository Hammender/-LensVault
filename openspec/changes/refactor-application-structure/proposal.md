## 为什么要做

当前后端 `main.py`、前端 `App.tsx`、统一 API 文件和全局样式文件集中承载了多个业务领域，已经形成明显的巨型入口和高耦合结构。项目同时缺少自动化回归测试，继续叠加功能会显著增加修改成本和行为回归风险，因此需要先建立清晰的模块边界和最低限度的测试护栏。

## 变更内容

- 将 FastAPI 应用创建、生命周期、依赖、权限、响应转换、媒体流处理和各业务领域路由从 `main.py` 中拆分。
- 将 React 应用壳、认证、工作空间、图库、人物、上传、视频、字幕和弹窗从 `App.tsx` 中拆分为类型明确的组件与领域控制器。
- 按业务领域拆分前端 API 客户端和全局样式，保持现有请求函数名称、Hash 路由、界面行为和样式效果。
- 增加后端 API 契约与权限回归测试，以及前端路由、API 客户端和视频续传队列等关键逻辑测试。
- 清理未被构建流程使用的临时修复脚本、无效通用 Context 和已提交的 TypeScript 构建缓存。
- 记录后续重构方向，包括大型媒体服务继续拆分、数据库迁移体系和代码规范工具，但不在本次第一阶段实施。
- 不修改现有 API 路径、HTTP 方法、请求响应结构、数据库表结构、本地存储协议和用户可见功能。

## 能力说明

### 新增能力

- `maintainable-application-structure`: 规定前后端模块边界、兼容性约束、可测试应用入口、回归测试护栏及后续重构记录要求。

### 修改现有能力

无。本次仅调整内部结构，不修改现有业务能力需求。

## 影响范围

- 后端主要影响 `backend/app/main.py` 及新增的应用工厂、路由、依赖、转换和后台任务模块。
- 前端主要影响 `frontend/src/App.tsx`、`frontend/src/api.ts`、`frontend/src/styles.css` 及新增的领域组件、hooks、API 和样式模块。
- 开发依赖将增加 pytest、httpx 和 Vitest；不增加 lint 或格式化工具。
- 生产部署方式、环境变量、MinIO、Qdrant、FFmpeg、ASR 和数据库数据不发生变化。
