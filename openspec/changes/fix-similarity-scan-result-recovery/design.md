## Context

相似扫描批次、分组和成员已经存入 SQLite，同范围的新成功扫描会原子替换旧成功结果。当前读取链路只根据前端内存中的 `person_id` 和 `include_cross_type` 查询精确范围，而页面刷新会把它们重置为默认值，因此其他范围的持久化结果失去入口。前端还使用同一个状态同时表示活动任务和展示结果，导致 pending、running 或 failed 扫描清空旧分组。

## Goals / Non-Goals

**Goals:**

- 刷新后恢复 workspace 最近一次成功扫描及其真实扫描参数。
- 允许查看每个扫描范围最近一次成功结果，包括已过期结果。
- 扫描进行中或失败时保持旧成功结果可读。
- 直接恢复现有数据库结果，不触发模型推理或数据迁移。

**Non-Goals:**

- 不保留同一范围的每一次历史快照。
- 不持久化“暂不处理”状态和删除勾选状态。
- 不修改相似度算法、阈值、向量 collection 或分组结构。

## Decisions

### 使用 workspace 级概览接口

新增 `/api/gallery/similarity-scans/overview`，返回唯一活动扫描以及各范围最近一次成功扫描。相比让前端遍历人物并重复调用精确查询接口，概览接口能在一次请求内恢复真实状态，也能统一执行 workspace 隔离和状态过滤。

成功结果以 `(person_id, include_cross_type)` 为范围键，每个范围只返回完成时间最新的一条，包含 `is_stale=true` 的结果。结果按 `completed_at`、`created_at` 倒序排列。失败记录不进入成功结果列表，pending/running 只通过 `active` 字段返回。

### 分离活动扫描与展示结果

前端使用独立的活动扫描和成功结果状态。活动扫描只驱动进度与轮询，成功结果负责分组分页和历史选择。开始重扫时不清空成功结果；成功后刷新概览并切换到新结果；失败后显示任务错误并继续展示原结果。

### 历史入口按范围展示

历史入口列出概览接口返回的成功结果，标签包含人物范围、跨类型状态、完成时间、分组数和过期标记。初次进入默认选择列表第一项，并同步扫描人物与跨类型开关。修改扫描范围时，如果该范围已有结果则展示它，否则显示尚未扫描的空状态。

### 保持现有发布和存储策略

扫描服务现有的同范围原子替换逻辑继续作为存储约束，不新增表或索引。现有 `/latest` 接口保留兼容，但相似整理页面改用 overview 作为状态来源。

## Risks / Trade-offs

- [人物和范围较多时概览列表增长] → 每个范围最多一条成功记录，当前规模最多约为人物数乘两种跨类型状态，响应量可控。
- [扫描期间用户切换历史结果造成状态混淆] → 活动扫描使用独立状态栏展示，历史选择只改变当前查看结果。
- [已删除人物的旧扫描 person_id 被置空] → 继续遵循现有外键行为，并以返回记录中的当前范围显示；本次不修改数据模型。

## Migration Plan

1. 新增响应 schema 和只读 overview 接口，无数据库迁移。
2. 前端切换到概览初始化和历史选择，保留现有创建、分组和删除接口。
3. 发布后当前数据库中的成功结果可直接重新显示。
4. 回滚时恢复原前端读取逻辑并移除新增接口，持久化数据不受影响。
