## Why

相似图片扫描结果已经持久化到 SQLite，但页面刷新后会把扫描范围重置为“全部人物且不跨类型”，随后只按这组条件精确查询，导致其他范围的成功结果无法恢复，看起来像扫描数据丢失。扫描进行中或失败时，前端还会清空已有分组，违背了原设计中“旧结果持续可读、失败保留旧结果”的约定。

## What Changes

- 提供 workspace 级扫描概览接口，分别返回当前活动扫描和各扫描范围最近一次成功结果。
- 相似整理页面刷新后自动打开整个 workspace 最近一次成功结果，并同步人物范围和跨类型设置。
- 增加历史结果入口，允许切换不同人物范围和跨类型组合保留的最近成功结果。
- 将活动扫描状态与当前展示结果分离；扫描中和扫描失败时继续展示旧成功结果。
- 已过期结果继续可读并明确提示，不要求用户重新执行耗时扫描才能查看。

## Capabilities

### New Capabilities

- `similarity-scan-result-recovery`: 规定相似扫描成功结果的跨刷新恢复、按范围历史访问、活动扫描展示和失败回退行为。

### Modified Capabilities

无。

## Impact

- 后端新增相似扫描概览读取 API 和响应类型，不修改数据库表结构。
- 前端相似整理页面调整初始化、轮询、重扫和历史选择状态管理。
- 当前已持久化的扫描、分组和成员可直接恢复，无需重新生成 DINOv2 特征或重新扫描。
