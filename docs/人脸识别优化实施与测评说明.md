## 一、历史翻转增强迁移流程（已由 AdaFace 迁移取代）

翻转增强同时作用于样本库和展示图库：对齐后的人脸分别生成原图向量和水平翻转向量，融合后作为最终 512 维向量。样本库向量和图库查询向量必须使用相同的预处理方式，不能让新查询向量直接匹配旧的非翻转样本向量。

因此，启用 `FACE_FLIP_AUGMENTATION=true` 后，推荐新建一套带独立向量版本的 Qdrant 集合。旧集合保留不动，整个过程不修改 SQLite 中的样本记录，也不修改 MinIO 中的图片对象。

### 迁移前检查

确认 Qdrant、SQLite 和 MinIO 可访问；确认没有其他任务正在写入样本库或执行图库识别。迁移期间不要使用 `--reuse-vectors`，因为它会复用旧的非翻转向量，无法完成预处理迁移。

当前本机配置已经开启翻转增强，但活动集合仍是旧版本时，应先保持以下两项不变，直到新集合校验完成：

~~~env
FACE_FLIP_AUGMENTATION=true
QDRANT_KNOWN_COLLECTION=pictureshow_known_faces_buffalo_l_v2_exif
FACE_EMBEDDING_VERSION=buffalo_l-v2-exif
~~~

### 创建新集合并重新提取样本向量

在项目根目录执行：

~~~powershell
cd E:\code\PictureShow
$env:PYTHONPATH="backend"
$env:PYTHONIOENCODING="utf-8"

conda run -n pictureshow python -m app.tools.rebuild_face_index `
  --collection pictureshow_known_faces_buffalo_l_v2_exif_fliptta `
  --embedding-version buffalo_l-v2-exif-fliptta `
  --centroid-mode mean
~~~

这里不要添加 `--reuse-vectors`，工具会重新读取每张样本图片，按当前翻转增强配置生成样本向量，并在新集合中重新生成 `centroid` 点。该命令不会删除活动集合；首次创建新集合时也不要使用 `--replace`。

命令结束必须确认：

- `ready_for_activation` 为 `true`；
- `skipped` 为 `0`；
- `missing_person_ids` 为空；
- `searchable_samples` 等于已就绪样本数量；
- `searchable_centroids` 等于有样本的人物数量；
- `invalid_payload_points` 和 `invalid_vector_points` 都为 `0`。

任一条件不满足，都不要切换 `.env`；保留旧活动集合继续运行，并根据 `skip_details` 修复样本后重新建立另一个实验集合。

### 切换活动集合

新集合校验通过后，修改项目根目录 `.env`：

~~~env
FACE_FLIP_AUGMENTATION=true
FACE_EMBEDDING_VERSION=buffalo_l-v2-exif-fliptta
QDRANT_KNOWN_COLLECTION=pictureshow_known_faces_buffalo_l_v2_exif_fliptta
FACE_DETECTION_SIZE=640
FACE_RECOGNITION_THRESHOLD=0.41
FACE_RECOGNITION_MIN_MARGIN=0.039
~~~

然后手工重启后端。重启前后都不要删除旧集合，旧集合是回滚依据。启动后可先运行只读检查：

~~~powershell
$env:PYTHONPATH="backend"
conda run -n pictureshow python -m app.tools.evaluate_unknown_gallery `
  --flip-augmentation `
  --threshold 0.41 `
  --output data/unknown-gallery-evaluation/fliptta-active
~~~

该检查只读取数据库、MinIO 和 Qdrant，并将报告写入 `data/`，不会改图库结果。

### 回滚

如果新集合出现异常，停止后端并把 `.env` 恢复为旧配置：

~~~env
FACE_FLIP_AUGMENTATION=false
FACE_EMBEDDING_VERSION=buffalo_l-v2-exif
QDRANT_KNOWN_COLLECTION=pictureshow_known_faces_buffalo_l_v2_exif
FACE_DETECTION_SIZE=640
FACE_RECOGNITION_THRESHOLD=0.43
FACE_RECOGNITION_MIN_MARGIN=0.039
~~~

重启后端即可回到旧集合。确认回滚稳定后，再决定是否保留新集合；不要在没有明确目标名称的情况下执行 `--replace` 或删除集合。切换后如果已经新增了只存在于新版本集合的样本，回滚前应先记录这些新增样本，避免旧集合看不到它们。

### 历史图库重识别

切换新集合后，先使用真正只读的预演：

~~~powershell
$env:PYTHONPATH="backend"
conda run -n pictureshow python -m app.tools.rerecognize_gallery `
  --only-unknown `
  --flip-augmentation `
  --threshold 0.41 `
  --audit-file data/face-rerecognition/fliptta-dry-run.jsonl
~~~

当前版本的默认 dry-run 只检测、匹配并写审计 JSONL，不会删除或插入数据库记录。只有明确提供 `--apply --confirm` 才会正式修改图库人脸记录和人物标签。正式执行前应检查审计结果，并按工作区或 `--limit` 分批处理。

## 二、上一轮中心向量优化的影响

上一轮新增了人物中心向量优化代码，主要包括：

- 将中心向量构建逻辑集中到 backend/app/services/face_profiles.py。
- 支持普通平均中心和稳健中心两种模式。
- 稳健模式会根据人脸尺寸、检测分数、清晰度和姿态对样本加权，并对明显离群样本降权。
- 增加样本向量的工作区、人物、来源类型和向量版本校验。
- 人物匹配保留原来的单张样本最高分逻辑；有限的“中心 + 多样本支持”加分默认关闭。
- 增强索引重建工具和历史重识别工具，但这些工具不会被程序自动调用。

当前默认配置仍然是：

~~~env
FACE_CENTROID_MODE=mean
FACE_MATCH_MAX_BONUS=0.0
~~~

因此，当前线上识别行为没有自动切换到稳健中心，也没有自动启用额外加分。普通平均中心和之前的简单平均在数学上基本等价，主要变化是中心计算代码统一了，并增加了向量完整性校验。

不需要因为这次代码修改立即手动重构向量库，也不需要修改数据库或 MinIO。只有在主动运行 rebuild_face_index 时，才会创建或写入新的 Qdrant 集合。旧的活动集合不会被该工具覆盖；工具也明确禁止把活动集合作为重建目标。

离线报告结果如下：

| 方案 | 已知人物召回率 | 已知人物拒识 | 错认人物 | 未知误接收 |
|---|---:|---:|---:|---:|
| 原始中心 | 83.58% | 120 | 1 | 33 |
| 稳健中心 | 83.31% | 122 | 1 | 32 |
| 稳健中心与有限加分 | 83.72% | 119 | 1 | 32 |

提升非常小，最佳方案只多找回 3 个查询，召回率提升约 0.14 个百分点。因此目前不建议切换到稳健中心，也不建议为追求这点收益而重建并替换生产索引。

报告还显示，漏识别主要来自分数低，而不是人物之间 margin 不足：737 个已知查询中，108 个最高分低于当前阈值 0.43，只有 12 个属于分数达到阈值但 margin 不足。侧脸样本召回率约 59%，小尺寸人脸约 60%，说明后续重点应放在检测尺寸、姿态和图库真实样本评估，而不是继续微调中心平均算法。

## 三、评估和实验是否影响生产数据

### evaluate_face_profiles

该脚本是只读评估：

- 读取 SQLite 中的样本照片和人脸记录。
- 从当前 Qdrant 活动集合读取样本向量。
- 在内存中进行留一法计算。
- 将报告写到 data/face-profile-evaluation/。

它不会写入真实生产数据库、不会写入 Qdrant、不会读取或写入 MinIO 中的图片对象。唯一的持久化变化是本地报告文件；data/ 属于运行时数据，不应提交到 Git。

### rebuild_face_index

该工具不是只读工具：

- --reuse-vectors 会读取当前 Qdrant 样本向量，并写入一个新的 Qdrant 集合。
- 不使用 --reuse-vectors 时，会读取 MinIO 样本图片并重新检测，然后写入新的 Qdrant 集合。
- 不修改 SQLite 和 MinIO。
- 默认不会覆盖当前活动集合；只有显式指定非活动目标集合并使用 --replace 时，才会删除并重建那个目标集合。

因此，运行索引重建前要确认目标集合名称；不要把活动集合名作为目标，也不要对仍需保留的实验集合使用 --replace。

### rerecognize_gallery

不带 --apply --confirm 时是预演模式：

- 读取 SQLite、MinIO 和 Qdrant，执行检测和匹配。
- 将审计记录写入指定 JSONL 文件。
- 默认 dry-run 不调用删除、插入或更新逻辑，只检测、匹配并生成审计记录；不会写入数据库、Qdrant 或 MinIO。
- 不写入 Qdrant，也不写入 MinIO。

带 --apply --confirm 时会正式写入图库人脸记录、人物标签和识别摘要，因此会改变真实 SQLite 数据库。它不会把图库人脸写回样本向量库，也不会修改 MinIO 图片对象。建议先执行 dry-run，再使用独立审计文件正式执行。

## 四、后续实验和测评计划

### 阶段一：中心向量方案保持保守

中心向量实验收益很小，因此继续保持 `FACE_CENTROID_MODE=mean` 和 `FACE_MATCH_MAX_BONUS=0.0`。翻转增强属于样本向量和查询向量的共同预处理变化，必须按本说明前面的迁移流程建立新集合，不能只改查询侧配置。

### 阶段二：对真实图库建立评估集

从已经人工纠正的人脸中建立真实图库评估集，重点统计“原先被判未知、后来人工确认属于样本库人物”的记录。评估应重新执行检测和匹配，统计：

- 已知人物召回率和拒识数量。
- 错认成其他人物的数量。
- 小脸、侧脸、模糊和遮挡分组结果。
- 处理耗时和检测失败数量。

这比单纯用样本库留一法更接近实际使用效果。

### 阶段三：检测因素实验结论

真实图库纠正集已经完成对照：640 检测加翻转增强优于无翻转配置；1024 检测尺寸会增加人脸框无法对应的问题，因此当前不启用 1024。当前推荐配置为 `FACE_DETECTION_SIZE=640`、`FACE_FLIP_AUGMENTATION=true`，阈值 `0.41`，最小 margin `0.039`。

### 阶段四：评估阈值和 margin 的分层策略

不建议直接把全局阈值从 0.43 大幅降低。应先用真实纠正集观察不同阈值和 margin 的组合，再考虑只对小脸、侧脸等低质量人脸采用较低阈值，并把低置信结果放入待审核状态。

### 阶段五：验证中心向量方案

只有当真实图库评估显示稳健中心确实改善召回率，才执行：

~~~powershell
$env:PYTHONPATH="backend"
conda run -n pictureshow python -m app.tools.rebuild_face_index --reuse-vectors --centroid-mode robust
~~~

确认输出 ready_for_activation: true 后，再切换 .env 中的 QDRANT_KNOWN_COLLECTION，重启后端，先观察新上传图片。不要直接删除旧集合，保留旧集合作为回滚依据。

### 阶段六：历史图库重识别

确认新索引在新上传图片上表现正常后，先预演：

~~~powershell
$env:PYTHONPATH="backend"
conda run -n pictureshow python -m app.tools.rerecognize_gallery --only-unknown --flip-augmentation --threshold 0.41 --audit-file data/face-rerecognition/fliptta-dry-run.jsonl
~~~

检查审计结果没有大规模异常，再正式执行：

~~~powershell
$env:PYTHONPATH="backend"
conda run -n pictureshow python -m app.tools.rerecognize_gallery --only-unknown --audit-file data/face-rerecognition/robust-apply.jsonl --apply --confirm
~~~

正式执行前应备份数据库，并保留审计 JSONL。若中途停止，可配合 --resume 继续处理同一审计文件。

## 五、结论

本机当前已经完成 AdaFace IR-101、翻转增强、独立阈值校准、新 Qdrant 集合和全图库正式迁移，不应再执行本说明中的旧 buffalo_l 翻转迁移命令。当前生产工作点是 640 检测、512 维 AdaFace、翻转增强、阈值 0.395、最小 margin 0.065、普通平均中心和关闭额外加分。

本轮证据表明收益来自更适合低质量人脸的识别模型和一致的翻转增强，并非来自提高向量维度。后续优先收集新上传图片中的人工纠正，按小脸、模糊、侧脸和遮挡分组持续复测；未知图库候选在没有人工真值前不得表述为正确识别。

## 六、迁移后全图库标签重整

AdaFace 迁移完成后，已依据迁移前数据库快照对全图库 28917 张图片逐图重整人物标签：迁移前已有未知人物标签的 186 张图片完全恢复旧标签；已知人物集合一致的图片只保留旧的已知人物标签并清理新增未知人物；集合不一致的图片分别增加“临时调试人物1”（318 张受保护来源）或“临时调试人物2”（226 张普通 auto 来源）供人工审核，临时人物均不绑定人脸。重整计划与当前数据库逐图差异为 0，两个临时人物的人脸绑定为 0。当前未知人物图片为 487 张，纯未知图片为 25 张。详见 `data/face-migration/gallery-tag-reconcile-summary.md` 和 `data/face-migration/gallery-tag-reconcile-verification.json`。
