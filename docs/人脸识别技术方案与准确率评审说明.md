# 人脸识别技术方案与准确率评审说明

整理日期：2026-10-01。代码基准：`91e502a`，结合当前工作区源码及本机 `.env` 中的人脸配置。

本文用于外部技术评审。描述分为当前实现、历史测评记录和待验证问题。未启动服务、未查询生产数据库或 Qdrant、未执行模型推理，因此配置不等于对运行中实例的确认，历史数字也不代表当前线上统计。本文不包含连接凭据。

## 一、系统定位与总体方案

系统面对的是“给定一个已登记人物样本库，为图库照片中的每张脸匹配人物，并允许拒识”的开放集人物识别任务。

当前采用预训练模型提取特征、向量检索及规则判定；上传样本只是增加参考向量和更新人物中心，不会训练或微调模型。不存在自动把全部图库识别结果回灌为样本的流程。

```text
人物样本图片 → EXIF 校正 → 人脸检测与五点对齐 → AdaFace 特征
           → 质量检查 → 单张样本向量 + 人物平均中心 → Qdrant

图库图片 → EXIF 校正 → 检测、对齐、倾斜校正 → AdaFace + 水平翻转融合
        → Qdrant 候选检索 → 按人物合并 → 分数和领先幅度判定
        → 必要时整图多角度重试、逐脸合并
        → 人物绑定 / 未知人物及待审核 → 人工纠正

人工纠正 → 修改绑定并保留纠正记录
显式“加入样本库” → 扩大人脸裁剪、重新检测 → 新参考样本
```

后端为 FastAPI；图片对象保存在 MinIO；人物、样本、图库、人脸结果和纠正事件由 SQLAlchemy 管理；参考特征保存在 Qdrant。当前依赖声明包括 InsightFace 0.7.3、ONNX Runtime 1.20.1、Qdrant 客户端 1.17.1。

未知人脸在当前主流程中统一归入工作区的“未知人物”，不是自动发现出的独立身份。`FaceService` 虽保留顺序式未知聚类函数和简单匹配函数，但全仓调用检索未发现它们被当前业务调用，不能把它们写成生产主算法。

## 三、检测、预处理和特征提取细节

### 3.1 解码与检测

1. Pillow 解码，先做 `ImageOps.exif_transpose`，再转 RGB、BGR 数组。
2. `FaceAnalysis(allowed_modules=["detection"])` 加载检测器；识别模块由独立适配器负责。
3. 检测结果必须包含有限数值的四维框和 `5 × 2` 关键点；无效框、空裁剪被丢弃。
4. 人脸按框面积从大到小排序；图库可以处理多张脸。
5. 检测器阈值、内部缩放与 NMS 未由本项目在此显式配置，实际值依赖所加载的 InsightFace 实现和模型，需要在运行环境另行记录。

### 3.2 五点对齐与模型输入

五点顺序为左右眼、鼻尖、左右嘴角。使用 `insightface.utils.face_align.norm_crop` 得到 `112 × 112` 对齐图。

AdaFace 适配器使用 **BGR**，张量布局为 `NCHW`，数据类型为 float32，按 `(像素值 - 127.5) / 127.5` 归一化。其他适配器可能使用 RGB，不能直接复用颜色通道假设。

当前翻转融合的准确公式是：

```text
z1 = 模型(对齐原图)
z2 = 模型(水平翻转后的对齐图)
e  = (z1 + z2) / ||z1 + z2||₂
```

两张图作为同一批次推理。代码先累加模型原始输出，再整体归一化；不是先将两条输出分别归一化再平均。如果模型输出范数不同，两种方法并不等价。

输出必须为 512 维，零向量或非有限输出会报错。相似度使用单位向量余弦相似度，数值不是经过校准的“身份正确概率”。

### 3.3 倾斜校正

由双眼连线估计滚转角，并用嘴部相对方向区分倒置。绝对角度达到 `30°` 后：

1. 以原框为中心，按最大边的 `1.5` 倍取正方形区域，越界处复制边缘。
2. 按估计角度旋转，再运行人脸检测。
3. 多脸时选择距离裁剪中心最近的人脸，重新对齐提取特征。
4. 校正成功时以校正特征为主，同时保留原始特征作为额外候选；校正失败退回原始关键点。

代码没有用“校正后的残余滚转角仍大”作为丢弃条件，也没有验证重检人脸与原目标的身份一致性；中心最近只是几何启发式。

### 3.4 整图多角度重试

有两个触发层次：

- 基础检测没有任何人脸时，尝试整图 `90°、-90°、180°` 检测。
- 图库主识别计划中，只要有一张脸未通过人物判定，就执行额外旋转流程；已经接受的原始人脸结果保持不变。

整图旋转扩展画布以保留内容，将新框和关键点映射回旋转前坐标。旋转候选之间按 `IoU ≥ 0.5` 去重，重复框的特征仍保存为变体；与原始人脸按 `IoU ≥ 0.3` 对应。

最终逐脸合并时，原始已接受结果保留；原始拒识脸仅在备选第一名分数更高时替换，随后执行阈值及 margin 判定；未与原框对应的新脸也加入结果。这里没有以完整的接受状态或 margin 作为备选方案排序依据。

如果原图检测到部分人脸且这些脸全部识别成功，不会主动启动整图旋转搜索其他漏检脸。因此多角度重试不是所有照片都执行的多角度全量检测。

## 四、样本库、索引与人物评分

### 4.1 样本入库

样本必须恰好检测到一张脸；无人脸、多脸或短边小于 40 像素不会成为就绪样本。尺寸不足 80、低检测分、模糊或较大侧脸均产生警告，但后几项不是硬拒绝条件。

质量指标实现如下：

- `face_size`：检测框短边。
- `blur_score`：人脸框裁剪转通道均值灰度，用离散拉普拉斯计算响应方差。
- `pose_yaw`：`(鼻尖横坐标 - 双眼中点横坐标) / 双眼距离 × 90`。

`pose_yaw` 是二维几何代理值，没有三维姿态求解；虽然显示为角度，但不宜当作精确头部偏航角。模糊度也未针对脸部尺寸或纹理做校准。

样本向量仅写入主特征，倾斜校正产生的备用特征不会全部入索引。入库后重新计算该人物中心；删除样本也需要维护对应参考向量和中心。

### 4.2 向量组织与版本隔离

同一 Qdrant 集合保存两类点：单张样本 `sample`、人物中心 `centroid`。使用 512 维 Cosine。载荷包含工作区、人物、样本编号、来源类型、向量版本。

查询按向量版本和来源类型过滤；工作区 ID 非空时增加工作区条件。业务最终还会从数据库检查候选人物是否属于目标工作区。底层查询在工作区为空时不增加该过滤，需确认所有实际入口的工作区约束。

读取参考向量构建中心时检查工作区、人物、来源类型、版本、维度、有限性及非零范数。索引健康检查比较就绪样本数、人物覆盖数、维度、距离类型及载荷完整性；常规健康检查不读取全量向量，不能等同于逐点特征正确性审计。

当前普通中心为：`c = normalize(mean(e1, e2, …, en))`。中心是独立候选，也可能比任何单样本得分更高。

### 4.3 当前评分和接受规则

对于同一待识别人脸的每个特征变体分别查询前 50 个向量点，再跨变体、跨样本及中心，按人物取最高分：

```text
S(p) = 所有已召回、属于人物 p 的候选分数的最大值
p1   = S 最大的人物
p2   = S 第二大且不同于 p1 的人物
margin = S(p1) - S(p2)
```

满足下列条件才自动接受：

1. 有候选，且数据库中存在该工作区的候选人物。
2. `S(p1) ≥ 0.395`。
3. 如果存在第二个人物，要求 `margin ≥ 0.065`。

只有一个人物候选时 `margin=None`，代码跳过领先幅度检查。前 50 个是向量点而非 50 个人，同一人物的多个样本可能占满候选。

同分时优先直接样本，再按样本编号和点编号稳定排序。当前关闭额外加分，所以不是投票制，也不要求多个参考样本同时支持。

### 4.4 已实现但未启用的策略

稳健中心至少三张样本时按尺寸、检测分数、模糊度和弱姿态因子加权；至少五张时，根据样本间余弦距离的中位数与 MAD 找离群样本，最多选配置比例（默认 20%），权重乘以 0.25，不是直接删除。

多样本加分需要至少两个不同样本和中心候选，第二样本达到支持下限。用中心分数与前若干样本平均分的较小值计算有上限的加分。当前上限为零，因此该策略不影响线上判定。

## 五、结果存储、人工纠正与重识别

图库人脸保存检测框、检测分数、预测人物、最终绑定、第一和第二候选的分数及来源样本、margin、拒识原因、识别适配器、向量版本、决策阈值以及质量指标。

拒识原因包括无候选、候选人物不存在、低于阈值和领先幅度不足。拒识脸设置 `needs_review=True`，绑定系统未知人物。没有检测到脸与检测到但拒识是不同情况。

图库查询特征不自动写入参考索引。人工绑定正式人物会更新图库关系，身份改变时记录纠正事件；“纠正绑定”不会自动让后续照片获得新的参考样本。

显式加入样本时，读取原图片，按人脸框扩大约 2 倍，检测不到再尝试 3 倍；必须单脸且满足尺寸门槛，再保存为 JPEG 样本并更新索引。相同图库照片对同一人物不能重复提升。已作为就绪样本来源的人脸不能直接改绑，需要先撤销样本。

当前落库字段不包含滚转角、是否校正、采用哪个变体、检测器文件摘要或整个处理流程版本。这些主要留在内存及日志，限制了后续审计重现。

重识别工具支持预演及审计，正式模式会重建图库人脸和部分人物标签。按当前代码，全量重识别并不无条件保留普通 `face_manual` 绑定；`manual/import/import_unknown/debug` 图片标签有保护，已提升为就绪样本的来源脸有重定位及身份保护。“只重识别未知”还有额外保护逻辑。不能依据旧说明概括成“所有人工绑定永不改变”。

| 历史实验 | 正确 | 错认 | 拒识 | 解释 |
|---|---:|---:|---:|---|
| 锁定验证集旧模型 | 97 | 5 | 67 | 合计 169 条 |
| 同验证集 AdaFace，0.395 / 0.065 | 109 | 5 | 55 | 正确增加 12，错认数量不变 |
| 569 条可对应纠正样本，AdaFace 不翻转 | 363 | 16 | 190 | 文档记录使用最终集合复测 |

最后一组应理解为相应索引背景下的配置对照，不能仅凭这些数字证明“库端、查询端两套完整对称重建”的因果收益。

历史中心方案实验中，原始、稳健、稳健加分方案的已知召回率分别约为 83.58%、83.31%、83.72%，提升很小，所以仍保持普通中心及零加分。历史文档也记录侧脸、小脸更困难，但属于当时数据和流程的结果。

文档记录迁移时有 793 个样本点、188 个人物中心，全图库重识别约 28917 张照片。这些是历史规模，不是当前实时规模。历史图库未知转已知、新增框或标签变化数量是审计指标，没有人工真值就不是准确率。

当前代码增加了方向校正、多变体择优和拒识重试，历史测评未证明这些组合在相同工作点下仍保持原错认水平。不能把旧验证集结果直接贴成当前系统准确率。

## 七、现有评估工具需要注意的问题

| 工具 | 当前用途 | 对评审的限制 |
|---|---|---|
| `evaluate_face_recognition` | 对纠正事件中的历史第一名分数扫阈值 | 不重新推理、不应用 margin、不按人脸取最后事件；100 条事件门槛不等于独立样本充足，未落实 20 人门槛 |
| `evaluate_face_profiles` | 样本留一法与中心策略对照 | 排除自身、同 SHA 和同来源图库照片；但样本分布不同于真实困难图库，近重复仍需检查 |
| `evaluate_gallery_corrections` | 原图重新检测，以框 IoU 对应纠正对象，再检索 | 不调用完整 `_recognition_plan`，缺少匹配拒识后的重试；没有排除已提升样本及其中心贡献；多个配置共享传入集合 |
| `calibrate_adaface_migration` | 根据实验报告校准分数和 margin | 按照片分层约 70/30 划分校准/留出，按旧未知、小脸、模糊、侧脸分层；仍需核验报告与参考库无污染 |
| `evaluate_unknown_gallery` | 对现有未知图片找候选 | 原先被系统判未知不代表真实身份未登记，候选不能算作正确找回 |
| `rebuild_face_index` / `rerecognize_gallery` | 索引版本迁移、图库预演与正式更新 | 属于工程与迁移工具，输出变化不自动构成准确率证据 |

尤其需要防止测试泄漏：图库纠正脸如果已经进入样本库，重测该脸会检索到自身或近似裁剪，并且人物中心也包含它。只删查询命中的那一个样本点还不够，必须在评估用参考库中移除关联来源并重算中心。

## 八、建议优先评审的准确率风险

以下为依据源码提出的审查项和实验假设，不是已经用真实数据证明的收益承诺。

### 优先级一：先保证评估可靠，再决定算法调整

**1. 评估必须复现完整线上决策。** 统一使用与图库相同的检测、重试、变体合并和判定路径，记录每条路径的独立表现。当前纠正集评估和线上存在明确流程差异。

**2. 多变体最大值需要重新校准。** 多个方向分别搜索并取最大值，会改变同人及异人得分分布。验证额外召回是否伴随未知误接收上升；分别对比“基础、翻转、倾斜校正、整图重试、全部组合”，阈值在校准集选取后锁定验证。

**3. 检查前 50 向量的候选挤占。** 对比当前检索与全量精确点积、扩大候选数、按人物召回等方案，观察第二人物是否缺失、margin 是否被高估。一个人物样本很多时，应单独测量其误接收率；单候选直接跳过 margin 也应独立审查。

**4. 冻结无泄漏测试集。** 参考库和查询集按原图来源、近重复组及拍摄序列隔离；已提升样本不能出现在自己的测试参考库中。照片级划分不能保证连拍或转载近重复不跨集合。

### 优先级二：检查输入和样本质量

**5. EXIF 坐标系存在潜在不一致。** 当前检测针对 EXIF 校正后的图像，`_face_fields` 直接保存该坐标；但 `_gallery_face_crop` 在未经方向校正的原像素上先按保存框裁剪，再旋转裁剪图。对方向非 1 的原始照片，可能裁错区域。应补充“原图上传→检测落库→提升样本”的整条路径测试，覆盖全部 EXIF 方向；现有裁剪单测采用原始坐标假设，不能替代此验证。

**6. 倾斜重检可能选错邻近人物。** 当前依据距裁剪中心最近选脸。多人贴近、原框偏移时，应核验目标位置映射、关键点和框一致性，统计误选与错认，不能只比较最终分数是否上升。

**7. 样本警告不阻止污染。** 低检测分、模糊、大侧脸仍可入库；最高单样本分数就能决定人物，错误样本影响可能大。建议先人工审查已有疑似错标、跨人混入和高重复样本，再评估分级入库、每人样本多样性以及数量不平衡。不要仅因是侧脸就删除，它也可能是必要的外观覆盖。

**8. 质量代理值需验证。** 横坐标偏航代理对滚转敏感，模糊分数受尺寸、纹理影响。当前普通中心并不使用质量权重；图库接受规则也没有直接使用这些质量指标。拟做质量分层阈值前，先验证分层是否可靠。

### 优先级三：评分、审计与可复现性

**9. 拒识备选按最高分合并。** 比较“最高分优先”与“完整接受条件、margin、几何可靠性共同选择”；对不同变体给出不同身份的情况单独统计，必要时送人工审核。

**10. 特征融合方式是实验项。** 比较原始输出求和后归一化与先单位化再融合；应同时重建实验参考库和查询向量，独立校准，不可只改查询侧。

**11. 流程版本与记录不足。** 当前向量版本名称体现模型和翻转，却没有自动绑定滚转、旋转等配置。建议评审模型摘要、检测器摘要、关键预处理参数和索引版本的关联，以及将最终候选所用方向和路径落到审计中的必要性。

**12. 人工真值保护与模型评价要分开。** 全量重识别可能覆盖普通人工绑定；评估真值应从独立冻结标签集读取，不能把已经被重新识别改写的业务结果当真值。

## 九、建议交给评审者的实验验收口径

先固定业务偏好：误认一个人物的代价和留作未知的代价分别是多少。不要以“未知数量下降”作为唯一成功条件。

至少报告以下指标，并同时给出分子、分母和置信区间：

- 检测召回：标注的人脸中检测到了多少；另外统计虚假检测框。
- 已知正确识别率：真实属于参考库人物的脸中，正确自动接受的比例。
- 已知错认率：已知脸被接受为其他人物的比例。
- 已知拒识率：已知脸被拒绝的比例；检测失败须另报或在端到端口径中明确计入。
- 真未知误接收率：身份确实不在参考库的人脸中，被绑定到已知人物的比例。
- 自动接受精确率：自动接受结果中真正正确的比例。
- 运行成本：每图耗时中位数及高分位数、多脸耗时、旋转触发率、每脸特征变体数。

测试集同时包含正常正确照片、历史纠正照片、独立真未知身份以及外观接近的不同人物；按小脸、侧脸、模糊、遮挡、倒置、多人、参考样本数量分组。已有纠正集适合找故障，不能代表全图库总体分布。

建议按以下顺序做受控实验，每次只改变一个因素：

1. 固定图片、人工真值和参考库快照，消除数据泄漏，建立当前完整流程基线。
2. 做检索全量对照，确认候选截断和缺失第二名影响。
3. 做方向校正及重试消融，重新校准阈值、margin，报告额外召回和新增错认。
4. 修复或确认坐标与样本身份问题后，比较清理样本前后结果。
5. 再实验质量分层、多中心或多样本支持；现有历史结果不足以支持直接开启稳健中心。
6. 最后才比较其他模型或更高检测尺寸，并把索引、对齐、阈值和延迟一起纳入对照。

所有候选方案都应在独立集合中重建参考向量，冻结测试后再决定是否切换。当前没有证据支持直接降低全局阈值或仅提高向量维度。
