# 识别异常案例

## 用途与入口

记录人工认为本应识别正确的人脸，以及无关人物被误认为库中人物的情况，供以后分析和模型测评。在展示图库详情的「人脸」页点击「记录识别异常」；图库工具栏「识别异常」打开案例库，路由为 `#/face-recognition-cases`。只支持已经检测出的人脸，不支持漏检人脸手动框选、自动诊断、自动训练或历史修正批量转换。

人工结论分为三类：

| 结论 | 参数与含义 |
| --- | --- |
| 是库中某个人物（`known_person`） | 必须指定当前工作区的正式人物作为正确人物，不受算法候选范围限制，没有就绪样本时仍可记录 |
| 确定是库外人物（`out_of_library`） | 确认此人不属于当前人物库，无需指定或创建人物 |
| 只确定不是某人（`not_person`） | 必须指定被排除的正式人物；真实身份未知，不能据此推断是库外人物 |

库中人物可选择「被判为未知」「认成其他人物」「其他异常」；后两种人工结论可选择「认成其他人物」「其他异常」。均可填写备注。已人工修正或已加入样本库的人脸也可记录。系统中的「未知人物」表示尚未确定身份，不作为正确人物或排除人物。

默认只保存案例。仅「是库中某个人物」提供「同时改绑为正确人物」，默认不选，勾选后沿用普通人脸绑定规则，案例与改绑同一事务提交，快照保留改绑前的信息。已加入样本库的人脸需先撤销样本才能改绑。后两种结论不改绑、不创建人物。记录不自动创建样本，也不更新模型或向量索引。

## 存档与时间含义

`face_recognition_cases` 按工作区保存案例。原始图片字节独立存放于当前 MinIO 桶的 `workspaces/{workspace_id}/face-recognition-cases/{case_id}/original`，保留 EXIF。删除原图库图片、人脸或人物不会删除案例；人物名称、原始编号和相关信息仍保存在快照中。人脸框坐标基于应用 EXIF 方向后的图像像素，`display_width`、`display_height` 是同一坐标系的尺寸。

新案例快照版本为 `schema_version=2`，历史版本 1 的快照保留原样，其人工结论均视为 `known_person`。主要包括：

| 数据 | 含义 |
| --- | --- |
| `photo` | 原图编号、名称、哈希、类型、尺寸、EXIF 与显示尺寸 |
| `recognition` | 源人脸记录中的算法结果：检测框、候选及分数、匹配来源与样本编号、拒识原因、阈值、版本和质量信息；缺失历史字段为空 |
| `binding_at_capture` | 点击记录时的绑定、标签来源和待复核状态，可能已经人工修改 |
| `correct_person` | 人工指定的正确人物编号及名称快照，后两种结论为空；兼容版本 1 |
| `ground_truth` | 版本 2 的完整人工结论：`answer_type`、正确人物和排除人物；未指定的人物为空 |
| `reference_samples_at_capture` | 记录时参考人物的样本清单：编号、哈希、状态、质量信息、来源、创建时间；`role` 区分正确人物、被排除人物、原绑定人物。库外人物参考原绑定的正式人物；没有时清单为空。不复制参考样本图片；版本 1 未标注角色时表示正确人物 |
| `configuration_at_capture` | 记录时的人脸配置和活动向量集合，不代表原识别时的完整配置 |
| `same_photo_sample_ids_at_capture` | 记录时由同一图库图片产生的样本编号，用于发现测评泄漏 |

源人脸的识别记录时间、案例记录时间和样本清单采集时间分别保存。不能把记录时的样本清单当作原识别时的样本库，也不能把当前人工绑定当作原自动绑定。未保存完整历史候选、查询向量、模型权重和原识别时的完整索引，不能声称案例足以精确重放全部历史计算。

同一人脸识别事件使用指纹去重；普通改绑不会新增同一事件的案例。提交时带详情版本标识，未记录过的事件若识别或绑定已经变化则返回冲突，要求刷新详情。同一事件再次提交返回已有案例，不重新执行可选改绑。重新识别产生的新事件可以再次记录。

## 案例库与导出

案例库支持按记录时相关人物名称（正确人物或排除人物）、人工结论、异常类型、向量版本筛选，按时间倒序分页。可查看存档原图及脸框、修改备注、返回仍存在的图库图片、删除案例。不修改人工结论和原始快照；标注错误时删除后重新记录。删除会清理案例自己的存档图片，不影响图库和样本库；清理失败的记录保持「待清理」并提供重试，不视为删除成功。创建案例失败且副本也清理失败时，尽可能登记待清理凭据；数据库本身不可写时在日志记录案例编号和对象键。

可导出勾选案例或所有符合当前筛选的案例。ZIP 内包含：

- `cases.jsonl`：逐条案例、完整快照、人工标注和包内图片路径。
- `summary.csv`：中文概要，含正确人物、人工结论、排除人物、异常类型、版本、时间、备注；对可能被表格软件解释为公式的文本加前缀保护。
- `images/`：原始图片，以哈希去重，保留原始字节。
- `说明.md`：字段、坐标、时间与测评使用说明。

导出不包含参考样本图片，不读取最新样本覆盖存档清单。原图缺失或哈希不一致时整体导出失败，不生成内容不完整但外观正常的包。导出使用系统临时目录，完成、失败或关闭响应后清理。

这批数据是人工挑选的困难案例，只能用于观察该集合上的表现，不能代表整体准确率。「只确定不是某人」仅能用于排除该人物，不能当作确定的库外人物；后两类结论不能当成库中人物的正样本。后续训练与测试需独立划分，按图片哈希及来源去重；排除图库图及其裁剪样本等同源材料，尤其注意记录前后将案例加入样本库造成的泄漏。

## 接口与权限

所有接口要求已登录并校验当前工作区。读取和导出允许工作区成员访问；新增、修改备注需要 `can_edit_gallery`，删除需要 `can_delete_gallery`，与前端一致。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/face-recognition-cases` | 创建或返回已有案例；参数含源图、人脸、详情版本、人工结论、正确人物或排除人物、异常类型、备注和是否同时改绑 |
| `GET /api/face-recognition-cases` | 相关人物名称／人工结论／异常类型／版本筛选和分页 |
| `GET /api/face-recognition-cases/{case_id}` | 案例详情及不可变快照 |
| `PATCH /api/face-recognition-cases/{case_id}` | 仅修改备注 |
| `DELETE /api/face-recognition-cases/{case_id}` | 删除或重试清理案例 |
| `GET /api/face-recognition-cases/{case_id}/original` | 工作区鉴权后的存档原图，支持范围读取 |
| `GET /api/face-recognition-cases/{case_id}/thumbnail` | 由存档原图生成的派生预览 |
| `POST /api/face-recognition-cases/export` | 按案例编号或筛选导出完整 ZIP |

图库人脸详情增加 `face_revision` 和 `recognition_case_id`，原有人脸接口保持兼容。案例后端入口为 `backend/app/api/face_cases.py`、`backend/app/services/face_cases.py`；前端入口为 `frontend/src/components/FaceCaseDialog.tsx`、`frontend/src/pages/FaceRecognitionCases.tsx`。

创建接口的 `answer_type` 默认 `known_person`，兼容原先只提交 `correct_person_id` 的客户端。负例必须清空 `correct_person_id`，`not_person` 另填 `excluded_person_id`，不允许同时改绑。列表及导出的 `answer_type` 支持三种值；保留原筛选参数名 `correct_person_name`，现匹配正确人物或排除人物的存档名称。
