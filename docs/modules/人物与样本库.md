# 人物与样本库

## 业务目标

维护人物及其样本人脸，作为图库自动识别的依据；把未匹配的人脸归入系统未知人物，便于后续修正。

## 关键流程

1. **图片标签管理**：`frontend/src/pages/PeoplePage.tsx` + `frontend/src/hooks/usePeople.ts`，入口名称为「图片标签」，保留 `#/people` 路由。页面分为人物标签和普通标签两种视图；桌面左右约为 7:3（右侧至少 340 像素），窄屏上下排列。接口 `/api/persons`（增删改、重命名、批量删除、导入导出）和 `/api/tags`。
2. **样本**：`POST /api/persons/{person_id}/samples` 上传样本；也可从图库照片设为样本（`/api/gallery/photos/{photo_id}/faces/{face_id}/sample`）。样本向量写入 Qdrant 已知人脸集合（默认 `pictureshow_known_faces`）。
3. **识别**：`backend/app/services/face.py` 检测与提取向量；`backend/app/services/face_index.py`、`backend/app/services/qdrant.py` 检索；`backend/app/services/face_profiles.py` 计算人物中心向量与聚合命中；`backend/app/services/importer.py` 的匹配计划决定绑定已知人物或未知人物。
4. **修正**：用户在图库详情改绑时写入 `FaceRecognitionCorrection`，并重新计算相关人物中心向量（`_recompute_person_centroid`）。
5. **重建/评估**：`backend/app/tools/rebuild_face_index.py`、`rerecognize_gallery.py` 及多个 `evaluate_*` 脚本，手动运行，说明见 `backend/app/tools/README.md`。

## 图片标签页面规则

- 人物列表支持名称、拼音、首字母搜索，并可选择一个普通标签筛选；两个条件取交集。筛选依据为人物与普通标签的直接绑定关系（`PersonTag`），不以同一图片上同时出现人物和普通标签作为绑定依据。无关联人物时显示空列表。
- 人物接口响应新增 `tag_ids`（直接绑定的普通标签编号，默认为空列表）；前端据此筛选和统计标签关联人数。列表批量加载绑定关系，无需逐个人物查询。此字段为兼容性扩展，不涉及表结构、配置或数据迁移。
- 人物详情优先展示前四张样本照片，可展开全部照片；每张照片的时间、状态、来源及删除操作放入其详情折叠区，从图库跳转到命中样本时自动显示该样本。改名、普通标签绑定/解绑、样本上传和删除人物放入照片下方的维护折叠区；导入导出及未知人物维护仍在列表底部。切换人物会重置详情滚动位置、收起维护区并丢弃未上传的样本预览，详情异步响应只更新当前选择的人物。
- 新建人物使用页头的独立入口和弹窗表单，与搜索、筛选区分开；支持取消、按 Esc 关闭及创建失败时保留输入。成功后关闭弹窗并选中新人物。
- 普通标签视图支持搜索、新建、改名、删除和查看直接绑定的人物；可跳转到人物详情或按当前标签筛选人物。删除标签前弹窗说明会解除人物和图库图片关联，保留人物和图片。系统标签在此页面只读。
- 普通标签增删改使用图库编辑权限；人物标签绑定使用样本编辑权限，解绑使用样本删除权限，与后端权限矩阵一致。绑定/解绑或删除普通标签后同步刷新人物关联及图库数据。

## 实现约定

- 未知人物由系统创建，不能被手动添加或绑定。
- 人脸模型与阈值来自 `.env`（`FACE_*` 等字段，见 `backend/app/core/config.py`）；改阈值前先用评估脚本验证，不要凭感觉调。
- Qdrant 向量维度需与模型一致（`QDRANT_VECTOR_DIMENSION`）；换模型需重建索引。
- 写入数据的 tools 脚本运行前确认目标数据库、Qdrant、MinIO 环境，需用户授权。
- 实际模型由部署环境的 `.env` 决定；`backend/app/core/config.py` 中 `face_model_name` / `face_adapter_id` 的代码默认值不代表每台设备正在使用的模型。
