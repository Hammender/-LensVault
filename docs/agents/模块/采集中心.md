# 采集中心

## 业务目标

从网站和 Telegram 批量采集图片、视频，经去重、质量检查和人工审核后导入图库或视频库。

## 关键流程

1. **来源与分类**：来源（`AcquisitionSource`，一个站点或 Telegram）下建分类（`AcquisitionCategory`，具体采集目标）；来源绑定采集脚本（`/sources/{source_id}/scripts`）。
2. **运行**：`POST /api/acquisition/categories/{category_id}/runs` 启动（服务端 `start_run`），`/runs/{run_id}/stop` 停止；下载并发、超时、重试由 `ACQUISITION_DOWNLOAD_*` 配置。
3. **素材审核**：下载结果为 `AcquisitionAsset`，初始状态 `pending_review`；状态有 `pending_review`、`importing`、`imported`、`import_failed`、`rejected`、`gallery_duplicate`，终态集合另含 `ignored_video`、`import_queued`、`ignored_protected`；只有 `pending_review` 或 `import_failed` 可以导入。`failed` 是采集条目/运行的状态，不是素材状态。前端审核灯箱 `frontend/src/components/AcquisitionReviewLightbox.tsx`，视频可抽帧截图（`/assets/{asset_id}/frames/...`、`/captures`）。
4. **导入**：`POST /assets/import` 生成导入批次（`AcquisitionImportBatch`），`/assets/reject` 拒绝；`/similarity/scan` 做采集侧相似检测；`/exports` 导出。
5. **插件**：非 Telegram 站点由管理员上传 ZIP 插件（`/api/acquisition/plugins`），每个版本独立 venv，在子进程中运行；可准备、启用、停用版本，管理凭据（用 `AUTH_SECRET_KEY` 加密）。
6. **Telegram**：内置能力，账号登录（手机号 + 验证码）、选择会话/论坛主题后按分类采集，见 `backend/app/services/telegram.py`。

采集接口前缀为 `/api/acquisition`，插件接口前缀为 `/api/acquisition/plugins`。

## 必须遵守的规则与常见坑

- Telegram 不做成插件；普通网站插件不增加单独登录页。
- 插件管理接口仅管理员（`User.is_admin`）可用；进程隔离不等于恶意代码沙箱，只安装可信插件。
- 插件凭据加密依赖 `AUTH_SECRET_KEY`，使用默认密钥会被拒绝；Telegram 会话加密用 `TELEGRAM_SESSION_ENCRYPTION_KEY`。
- 采集相似候选与图库相似图是两套数据。
- `backend/app/services/acquisition.py` 很大（近 3000 行），改动前先定位具体函数并追踪调用方。
- 改素材状态流转前先通读 `backend/app/services/acquisition.py` 相关函数与测试。
