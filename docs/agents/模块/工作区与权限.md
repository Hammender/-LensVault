# 工作区与权限

## 业务目标

多用户登录，并按工作区（内容空间）隔离数据；所有者可邀请成员并按开关授予增删改权限。

## 关键流程

1. **初始化与登录**：`GET /api/auth/bootstrap-status` 判断是否需要初始化；`POST /api/auth/bootstrap` 创建首个账号（`is_admin=True`）；`/api/auth/login`、`/register`、`/me`、`/logout`。登录页 `frontend/src/components/AuthScreen.tsx`。
2. **鉴权**：`backend/app/dependencies/context.py` 的 `require_context` 读取 `Authorization: Bearer`，GET/HEAD 请求也接受 Cookie `pictureshow_session`；令牌由 `backend/app/services/auth.py` 签发，有效期 `ACCESS_TOKEN_EXPIRE_MINUTES`。
3. **选择工作区**：请求头 `X-Workspace-Id` 或查询参数 `workspace_id`；未指定时优先用户的私人空间。每个用户首次访问时自动创建私人空间（`ensure_private_workspace`），自己为 `owner`。
4. **权限**：`owner` 拥有全部权限；`member` 按 `WorkspaceMember` 的 9 个开关：`can_add_gallery`、`can_delete_gallery`、`can_edit_gallery`、`can_add_samples`、`can_delete_samples`、`can_edit_samples`、`can_add_videos`、`can_delete_videos`、`can_edit_videos`。路由与权限的对应关系集中在 `ROUTE_PERMISSION_MATRIX`，由 `enforce_request_permission` 自动校验。
5. **成员与邀请**：`/api/workspaces/...`（成员、邀请、离开），`/api/workspace-invitations/...`（接受、拒绝），`POST /api/admin/users` 管理员建号。前端 `frontend/src/components/WorkspacePanel.tsx`、`frontend/src/components/PermissionEditor.tsx`。

## 名词

工作区（私人空间 `kind="private"`）、所有者、成员、邀请、管理员（`User.is_admin`，系统级，与工作区角色不同）。

## 必须遵守的规则与常见坑

- 新增写操作路由时，必须在 `ROUTE_PERMISSION_MATRIX` 登记对应权限，否则成员可越权调用。
- 前端 `hasPermission` 与后端 `has_permission` 逻辑保持一致（owner 恒为真）。
- 所有业务查询必须按 `current.workspace_id` 过滤，避免跨工作区泄露。
- 私人空间有特殊限制（如 `backend/app/api/workspaces.py` 中对 `kind == "private"` 的判断），具体限制项待确认。
- `AUTH_SECRET_KEY` 默认值仅用于本地开发；生产必须在 `.env` 中替换。
