# 图库

## 业务目标

浏览和整理已入库的人物写真。观感优先，同时让用户在列表页一键打开详情、高效修正每次导入后识别错的人物或被识别为「未知」的已知人物。

## 关键流程

1. **导入**：上传页（`frontend/src/pages/UploadPage.tsx`）调用 `POST /api/gallery/photos/import`（普通图）或 `POST /api/gallery/rich-photos/import`（图文），返回后台任务；也可导入导出包 `POST /api/gallery/photos/import-zip`。导入时做人脸检测与匹配，匹配不到的人脸绑定到系统未知人物。
2. **列表**：`GET /api/gallery/photos` 分页、筛选；按图片编号（主键）精确搜索由 `frontend/src/lib/galleryPhotoIdSearch.ts` 解析输入。列表用预览图 `.../thumbnail`（动图 `.../animated-thumbnail`），原图 `.../original` 只在详情与灯箱加载。
3. **瀑布流**：`frontend/src/lib/galleryMasonryPack.ts` 按宽高比估算高度，高的先放、放到最短列，只调整当前页内的显示顺序。Shift 范围选择按视觉顺序（`flattenGalleryMasonryVisualOrder` + `frontend/src/lib/gallerySelection.ts`）。
4. **详情修正**：卡片「详情」按钮打开详情面板，可改绑/解绑人脸（`PATCH|DELETE /api/gallery/photos/{photo_id}/faces/{face_id}/person`）、增删人物和普通标签、设为样本、编辑图文、单张重识别（`POST .../re-recognize`）。批量：`re-recognize-unknown`、`clear-unknown-tags`、`batch-delete`。
5. **灯箱**：`frontend/src/components/PhotoLightbox.tsx` + `frontend/src/hooks/useGalleryLightbox.ts`；按卡片实际位置从上到下、从左到右翻页（`frontend/src/lib/galleryLightboxOrder.ts` 的 `sortGalleryLightboxPositions`，`frontend/src/pages/GalleryPage.tsx` 中 `readGalleryLightboxOrder` 读取）；Shift 范围选择则按列优先的视觉顺序（`frontend/src/lib/galleryMasonryPack.ts` 的 `flattenGalleryMasonryVisualOrder`），两者不同是有意设计。
6. **导出**：`GET /api/gallery/photos/export` 及按选择导出，打包 ZIP。

## 必须遵守的规则与常见坑

- 浅色/奶油色主题；筛选默认展开；卡片人名完整显示在图片下方、不遮挡画面；卡片不显示图片编号和普通标签；「详情」按钮常驻、一键可达。
- 灯箱保留右侧竖向信息栏（与图片区等高，后续还要加内容），不改成横向底栏；不要把完整修正面板塞进灯箱。
- 静态预览图按请求宽度（默认 480，最大 2048）归到 `PREVIEW_EDGES` 档位（160～2048，见 `backend/app/services/thumbnails.py`），缓存于 MinIO `derived/gallery-thumbnails/v2/...-{edge}.bin`；只有动图预览固定最长边 720（`ANIMATED_THUMBNAIL_MAX_EDGE`）。不要在列表直接加载原图。
- 系统未知人物不能手动添加为人物标签或手动绑定（后端返回 400）。
- 照片人物变化会使相似图扫描结果过期（`mark_similarity_scans_stale`），改动导入/修正流程时注意保持调用。
- 修改列表接口参数需同步契约快照和 `frontend/src/api/gallery.ts`。
- 导入任务的并发数由 `GALLERY_RECOGNITION_WORKERS` 等配置控制（`backend/app/core/config.py`）。

## 素材来源与迁移包（2026-10）

- 图片、图文的 `created_by` 表示当前工作区入库人；异步任务持久化操作人及名称快照。正式来源由 `MediaProvenance` 保存，与图片同事务提交，重复入库不覆盖来源或入库人。
- 列表、详情返回 `source_summary`，灯箱及详情信息栏点击来源后请求 `GET /api/gallery/photos/{photo_id}/source`。来源详情按工作区隔离，对当前工作区所有成员可见；列表不读取详情 JSON。
- 图库 ZIP 默认导出 `gallery_export` v3，携带来源快照；导入兼容 v1、v2、v3。旧包记录本次导入人，上游来源未知。新包保留原始来源但不将包中身份绑定为本地账号；重复导入沿用原有标签等合并逻辑，来源及入库人不覆盖。v3 包需要新版程序读取。
- 来源保留本次入库信息和一层原始上游，不无限累积搬运记录；截图保留原视频及帧时间快照。来源信息可以脱离原站点、分类和采集任务长期保留。超过 64 KiB 的快照按「公共元数据 → 原始上游 → 长字段」顺序裁剪并打标记，不再让单条入库失败。
- 待审核素材的来源快照同时冻结在 `AcquisitionAsset.source_snapshot_json` 上，审核期间删掉站点或分类后，入库仍能取到站点与分类。
- 相关实现：`backend/app/models/provenance.py`、`backend/app/services/provenance.py`、`backend/app/api/provenance.py`、`frontend/src/components/MediaSource.tsx`。历史回填见 `backend/app/tools/README.md`。

- ZIP 清单上限16 MiB，单张图片上限128 MiB；拒绝不安全路径及无效来源快照，不导入凭据或临时下载地址。凭据过滤同时覆盖 `auth`、`key`、`sig`、`jwt` 等字段名。
- 图库 ZIP 导出预加载来源快照与 Telegram 信息，避免逐图查询。
