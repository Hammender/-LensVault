# 工作区与权限改动规范

## 改动前阅读

登录、工作区选择、角色和邀请流程见 [工作区与权限说明](../../modules/工作区与权限.md)。

## 工作约束

- 新增写操作路由时，在 `ROUTE_PERMISSION_MATRIX` 登记对应权限，防止成员越权。
- 前端 `hasPermission` 与后端 `has_permission` 保持一致，所有者权限逻辑不能仅在前端实现。
- 所有业务查询和对象读取按当前工作区过滤；改接口时覆盖跨工作区拒绝访问的情况。
- 区分系统管理员和工作区所有者，不用系统身份替代工作区成员权限。
- 保持私人空间自动创建、优先选择及不能退出的约束。
- 不把默认开发密钥视为可部署的生产凭据；真实密钥只保存在本机配置。

## 关键代码与验证

- 后端入口：`backend/app/dependencies/context.py`、`backend/app/api/system.py`、`backend/app/api/workspaces.py`、`backend/app/services/auth.py`。
- 前端入口：`frontend/src/lib/permissions.ts`、`frontend/src/components/WorkspacePanel.tsx`、`frontend/src/components/PermissionEditor.tsx`。
- 按改动运行 `backend/tests/test_permissions.py`、`backend/tests/test_api_request_context.py`、`backend/tests/test_workspace_name_constraints.py` 及前端权限测试；前端改动执行构建。
