# 采集中心改动规范

## 改动前阅读

采集流程、状态、接口与来源快照见 [采集中心说明](../../modules/采集中心.md)；插件契约见 `docs/采集插件开发规范.md`；Telegram 行为见 `docs/telegram-dialog-topic-acquisition.md`。

## 工作约束

- Telegram 使用内置采集能力，不另做插件；普通网站插件不增加单独登录页。
- 插件管理接口仅系统管理员可用；进程隔离不等于恶意代码沙箱，只安装可信插件。
- 保持插件凭据与 Telegram 会话的加密处理，不回显密钥或会话内容。
- 采集相似候选与图库相似图是两套数据，不混用状态、结果或删除逻辑。
- `backend/app/services/acquisition.py` 逻辑较多，先定位具体函数和调用方；改状态流转前通读相关处理及测试。
- 素材侧首次来源快照只写一次，分类或站点删除不得破坏正式来源；来源与素材入库保持事务一致。
- 公开来源只读取插件主动声明的 `public_metadata`，不从 `plugin_data`、凭据或账号参数回退；保留递归脱敏及无效元数据降级处理。
- 修改 Telegram 评论采集时保持根频道来源键稳定，不用讨论组标识替换；发送形式与内容类型分别处理。
- 历史回填操作按 `backend/app/tools/README.md` 先试跑并核对报告，只在用户授权范围内写入。

## 关键代码与验证

- 后端入口：`backend/app/services/acquisition.py`、`backend/app/services/acquisition_frames.py`、`backend/app/services/acquisition_adapters/`、`backend/app/services/acquisition_plugins/`、`backend/app/services/telegram.py`。
- 前端入口：`frontend/src/pages/AcquisitionCenter.tsx`、`frontend/src/components/AcquisitionReviewLightbox.tsx`、`frontend/src/components/AcquisitionPluginsPanel.tsx`。
- 按改动运行 `backend/tests/test_acquisition*.py`、`backend/tests/test_telegram_acquisition.py`、`backend/tests/test_media_provenance.py`、`backend/tests/test_pending_asset_source_backfill.py` 及相应前端测试；前端改动执行构建。
