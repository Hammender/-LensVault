# 采集插件开发规范

采集插件负责不用登录即可按页下载的网站：页面适配和原始媒体下载。PictureShow 负责运行记录、去重、图片分析、视频探测、待审核和正式入库。管理员只安装可信插件；插件代码在独立子进程及独立 Python 环境运行，进程隔离不等于恶意代码沙箱。

Telegram 频道是内置采集能力，使用采集中心原有的账号登录、会话和频道流程。不要把 Telegram 做成插件，也不要为普通网站插件增加单独的登录页。

## 插件包

ZIP 根目录至少包含 `plugin.json`、`plugin.py` 和中文 `README.md`。`README.md` 必须说明适用网站、支持的媒体、采集目标和参数的含义。插件不声明凭据时，说明里写明无需登录。不得把真实 Cookie、Token、密码或浏览器导出文件放进插件包。

目录完成后可运行 `python -m app.tools.package_acquisition_plugin 插件目录 --out 输出文件.zip` 生成上传包。`examples/acquisition-plugin-json-api/` 是唯一随仓库提供的示例，不对应真实网站，也不随主程序启用。新环境的脚本列表只有内置的 Telegram 频道；其他网站只有在管理员上传并启用对应插件后才会出现。

`plugin.json` 的协议版本固定为 `1`；`key` 使用小写字母、数字和连字符，发布后保持稳定；`version` 使用 `主版本.次版本.修订版本`。升级须使用新的版本号，同一版本不可覆盖。`page_format_key` 用于限制同一站点绑定的脚本兼容性。`entrypoint` 是包内 Python 文件路径。`requirements` 声明插件所需的 Python 包，管理员上传后显式点击“准备环境”才会安装。主程序不默认安装浏览器。

`parameters` 使用主程序已有的脚本参数结构，字段类型支持文本、整数、数字、布尔值、选项、时间与文本列表。`credentials` 可省略或留空。只有插件确实要携带可选请求头一类信息时才声明凭据；每项包含 `key`、中文 `label`、`required` 和 `secret`。只有存在 `required: true` 字段时才强制选择已验证账号；全部字段可选时可以不选择账号，插件收到空凭据对象。主动选择账号时仍必须通过连接测试。`required` 和 `secret` 必须使用 JSON 布尔值。秘密字段在界面隐藏，并按工作区加密保存；插件在子进程调用时取得相应配置。不要在插件输出、异常和采集结果中回显这些值。无需登录的插件不要声明凭据，界面也不会要求维护账号。

## 入口函数

入口文件提供以下函数，具体字段与可运行示例见 `examples/acquisition-plugin-json-api`：

```python
def test_connection(credentials: dict) -> dict:
    return {"ok": True}

def enumerate_pages(crawl_url: str, parameters: dict, credentials: dict,
                    known_external_keys: set[str], incremental: bool):
    yield {"page_number": 1, "items": [], "stop_reason": "collection_end"}

def download(item: dict, credentials: dict, temporary_dir: str) -> dict:
    return {"path": "/由插件写入指定临时目录的媒体文件"}
```

`test_connection` 在插件声明了凭据时验证这些配置是否可用，返回 `{"ok": true}` 才显示连接正常。未声明凭据时可以直接返回 `{"ok": true}`。`enumerate_pages` 逐页输出，单个条目至少有稳定的 `external_key` 和原始 `source_url`；图片、视频分别设置 `media_type` 为 `image` 或 `video`。可附带 `title`、`preview_url`、`candidate_urls`、`referer_url` 和 `plugin_data`。`published_at` 使用 ISO 8601 时间；带时区的时间统一转为上海时间，无时区时间按上海时间解释。无效的可选发布时间会被忽略并记录警告，已有历史异常值也不会阻止审核列表读取。每页需要正整数 `page_number`，末页填写 `stop_reason="collection_end"`；用户指定页数结束时填写 `requested_end`。稳定来源键在同一目标和插件范围内用于增量与失败重试。

`download` 将媒体逐块写入主程序指定的临时目录并返回文件路径。主程序检查路径和大小，计算哈希并处理媒体；插件不得直接写图库数据库或 MinIO。较大的视频应逐块下载，避免一次读入内存。运行中异常会记录在采集任务中；凭据失效时应抛出清楚的中文错误，便于用户更新账号后重试。

## 安装与版本

系统管理员上传 ZIP 后先校验包结构，随后手动准备独立 Python 环境并启用版本。一个插件同一时刻只有一个启用版本；正在运行的任务沿用其创建时记录的版本。停用只阻止新任务，历史来源与审核结果继续保留。内置脚本标识不能当作插件上传。插件若声明了凭据，工作区所有者可以保存并测试；普通采集权限沿用现有设置。

网页提供“试采前 3 项”，用于验证普通网站插件的枚举、下载和媒体分析，完成后清理临时文件，不创建采集历史或待审核资产。插件版本升级后，已保存的凭据需重新测试；卸载版本或删除凭据时，历史记录保留，但正在使用的任务会阻止操作。

以后生成插件的 AI Agent 应输出符合本规范的 ZIP 与中文说明，并运行结构、接口和小量采集检查。AI Agent 本身属于后续任务。

## 运行与资源边界

当前运行方式支持单个后端进程。插件目录采用整体快照替换，管理操作串行执行；正式采集、试采和连接测试会持有版本使用引用，调用未结束时不能卸载该版本。已经开始的任务固定使用运行记录中的版本及执行开始时读取的凭据，之后更新账号不会改变该任务的请求内容。连接测试期间更新账号、删除账号或切换版本，会使旧测试结果失效，接口提示重新测试。

插件的虚拟环境继续独立于主程序，协议 worker 由当前主程序提供，更新主程序无需重新上传插件包。枚举输出最多缓存 4 条消息；每条枚举输出或单次调用结果最多 2 MiB，错误输出最多 4 MiB。输出超限会停止调用，错误内容先脱敏再截断。枚举只有在等待下一条消息时才计算空闲时间，处理已收到页面的下载耗时不计入该时间。

每次运行或试采拥有独立临时根目录，下载可在指定目录中创建子目录和附属文件。正常结束、失败或用户停止时，主程序关闭枚举、回收子进程及已开始的下载，再清理本次创建的整个目录。此流程不清理其他运行或历史遗留目录。停止期间已经进入媒体分析的工作会完成收尾后释放文件。

部署此变更只需重启后端，无需修改配置或执行数据库迁移。此版本仍不提供多后端进程之间的任务协调。

## 可公开的素材来源数据

枚举条目可新增 `public_metadata` 对象，用于素材入库后向工作区成员展示来源补充信息。旧插件不提供该字段仍可运行。`plugin_data` 继续只用于插件工作流，不会直接复制为公开来源。

公开元数据只应包含适合展示的字段（例如作品编号、作者、栏目）。不得包含 Cookie、Token、密码、账号参数、请求头或签名下载地址；主程序会递归过滤敏感键及常见凭据文本，清理 URL 中的凭据参数。总大小限制16 KiB、嵌套深度最多4层，超限保留截断标记。过滤无法识别所有伪装秘密，插件作者仍必须保证此对象可公开。若 `public_metadata` 不是对象，主程序会丢弃该字段并记录警告，不影响同一条目其余信息。
